# 一期 A 后端本地开发说明

[返回文档导航](../README.md)

使用 Java 17 和 Maven 3.9 及以上版本。Spring Boot 3.3.4 统一管理 Flyway 10.10.0 及其必需的 `flyway-database-postgresql` 模块，不单独覆盖 Flyway 版本。此前的 Boot 3.0.7/Flyway 9.5.1 基线早于 PostgreSQL 16 支持版本。项目以 PostgreSQL 16 为事实数据来源，Redis 仅用于可重建缓存和协调，MinIO 仅存储头像。不为本项目另起第二套中间件，也不引入 H2 或 Testcontainers。

本文中的命令供后续获准操作时参考。本轮只修改代码与文档，未执行测试、编译、启动、迁移、联调或容器构建。

## 现有中间件

现有获授权使用的编排文件为 `E:\zahuo\实习上简历\procurement-实习的项目\deploy\docker-compose.yml`。运维人员获得相应授权后，仅启动或复用所需服务：


## 数据库准备

应用和测试分别使用 `study_copilot_app`、`study_copilot_test_runner` 登录角色，并分别设置密码。下文仅列出凭据环境变量名，实际值来自密钥管理服务或私有进程环境，不写入版本控制或命令记录。

获授权的运维人员可进入现有 PostgreSQL 容器管理会话：

```powershell
docker compose -f 'E:\zahuo\实习上简历\procurement-实习的项目\deploy\docker-compose.yml' exec postgres sh -c 'psql -U "$POSTGRES_USER" -d postgres'
```

仅对尚不存在的角色或数据库执行以下 SQL。使用交互式 `\password` 设置各角色密码，避免明文进入命令历史：

```sql
CREATE ROLE study_copilot_app LOGIN;
\password study_copilot_app
CREATE ROLE study_copilot_test_runner LOGIN;
\password study_copilot_test_runner
CREATE DATABASE study_copilot OWNER study_copilot_app;
CREATE DATABASE study_copilot_test OWNER study_copilot_test_runner;
```

应用库和测试库的所有者保持隔离，不授予任一角色访问其他项目数据库的权限。Flyway 在各库内创建 `study_copilot` 模式。V2 在其中安装 PostgreSQL 受信任扩展 `btree_gist`，数据库所有者无需超级用户权限即可安装。如果扩展已安装在其他模式，迁移前由运维人员核对位置，不要直接移动共享扩展。

## 环境变量与运行配置

默认运行配置不内置凭据。为应用进程提供以下变量：

| 环境变量 | 用途 |
| --- | --- |
| `SC_DB_URL` | `jdbc:postgresql://127.0.0.1:5433/study_copilot?currentSchema=study_copilot`，按实际主机和端口调整 |
| `SC_DB_USER`、`SC_DB_PASSWORD` | 应用数据库登录凭据 |
| `SC_REDIS_HOST`、`SC_REDIS_PORT`、`SC_REDIS_PASSWORD` | 现有 Redis 连接，主机与端口默认 `127.0.0.1:6381` |
| `SC_REDIS_PREFIX` | 运行命名空间，默认 `study-copilot:` |
| `SC_JWT_SECRET` | 至少 32 个 UTF-8 字节的随机 JWT 签名密钥 |
| `SC_IDEMPOTENCY_HMAC_SECRET` | 至少 32 个 UTF-8 字节的独立随机密钥，用于注册请求指纹；不随 JWT 签名密钥或签发者轮换 |
| `SC_RECOVERY_SUPPORT_CHANNEL` | 受邀内测账户的人工恢复渠道，测试环境外必填 |
| `SC_MINIO_ENDPOINT` | 现有 MinIO 接口地址，默认 `http://127.0.0.1:9000` |
| `SC_MINIO_BUCKET` | 独立头像存储桶，默认 `study-copilot` |
| `SC_MINIO_ACCESS_KEY`、`SC_MINIO_SECRET_KEY` | 仅限该头像桶的访问凭据 |
| `SC_METRICS_TOKEN` | `/actuator/prometheus` 的可选独立访问令牌；未配置时拒绝访问 |
| `SC_FOCUS_SCAN_DELAY_MS` | 到期会话扫描间隔，默认 `1000` 毫秒 |
| `SC_ACCOUNT_DELETION_SCAN_DELAY_MS` | 账户清理扫描间隔，默认 `30000` 毫秒 |

私有头像桶由获授权的 MinIO 运维人员创建，对象路径按用户隔离。当前已交付存储实现和 V6 附件元数据，但本轮未编译或运行。客户端延迟创建，启动时不请求 MinIO；缺少 MinIO 凭据时仅头像操作不可用，不阻止核心应用启动。私有桶、鉴权图片读取及账户清理重试要求见 [运维说明](../05-运维部署/后端运维手册.md)。

后续获准运行时，可使用：

```powershell
mvn -f backend/pom.xml spring-boot:run
```

### 独立测试配置

`test` 配置仅通过 `SC_TEST_DB_URL`、`SC_TEST_DB_USER`、`SC_TEST_DB_PASSWORD` 连接数据库。`SC_TEST_DB_URL` 使用 `jdbc:postgresql://127.0.0.1:5433/study_copilot_test?currentSchema=study_copilot`，主机和端口按实际环境调整。在创建数据源和 Flyway 前，程序拒绝任何名称不等于 `study_copilot_test` 的数据库，仅在查询参数中出现该名称不能通过校验。同时校验 Hikari、Flyway 地址覆盖，并拒绝 JDBC `PGDBNAME` 查询覆盖，包括百分号编码形式。Flyway 清库功能关闭，测试不得清理共享 Redis 或无关数据库模式。

测试 Redis 命名空间与 Spring 缓存前缀固定为 `study-copilot:test:`、`study-copilot:test:cache:`。涉及 Redis 的测试需提供 `SC_REDIS_PASSWORD`；纯迁移测试不需要 Redis 或 MinIO 连接。可通过 `SC_TEST_JWT_SECRET` 覆盖明确仅用于测试的签名密钥，默认运行配置不会使用该测试密钥。

**仅在用户明确批准执行测试后**，才可运行以下命令：

```powershell
mvn -f backend/pom.xml -Dspring.profiles.active=test -Dtest=MigrationSmokeTest test
mvn -f backend/pom.xml -Dspring.profiles.active=test test
```

两条命令都需要配置三个 `SC_TEST_DB_*` 变量。仓库还提供管理凭据生命周期的包装脚本：为 `study_copilot_test_runner` 设置一次性密码，经环境注入，执行后清除，不写入磁盘或命令记录。

```powershell
powershell -NoProfile -File scripts/run-tests.ps1
powershell -NoProfile -File scripts/run-tests.ps1 -Selection "AuthApiTest"
```

脚本默认访问 `procurement-stack-postgres-1` 容器、端口 `5433`。测试环境不同时，可通过 `SC_PG_CONTAINER` 和 `SC_TEST_DB_URL` 覆盖。

### 不改动共享服务的独立测试环境

修改共享 PostgreSQL 容器中的角色密码，会写入其他项目也使用的服务。若后续获准使用独立临时测试容器，可避免此类共享写入；这属于默认复用现有中间件方案之外的选择，本轮未创建容器。Flyway 会创建 `study_copilot` 模式，临时数据库必须准确命名为 `study_copilot_test`，且测试登录角色为数据库所有者。

```powershell
docker run -d --name sc-test-pg -e POSTGRES_HOST_AUTH_METHOD=trust -e POSTGRES_USER=postgres -p 127.0.0.1:5434:5432 postgres:16-alpine
docker exec sc-test-pg psql -U postgres -d postgres -c "create role study_copilot_test_runner login"
docker exec sc-test-pg psql -U postgres -d postgres -c "create database study_copilot_test owner study_copilot_test_runner"
```

随后配置包装脚本的目标环境：

```powershell
$env:SC_PG_CONTAINER = 'sc-test-pg'
$env:SC_TEST_DB_URL = 'jdbc:postgresql://127.0.0.1:5434/study_copilot_test?currentSchema=study_copilot'
powershell -NoProfile -File scripts/run-tests.ps1
```

`POSTGRES_HOST_AUTH_METHOD=trust` 仅适用于绑定本机回环地址、用后销毁的临时容器，长期环境必须使用真实密码。测试配置会拒绝名称不等于 `study_copilot_test` 的数据库，该名称不能随意修改。

## 数据库结构与功能边界

### 跨资源写入的加锁约定（任务 4–8）

设置、学习日规则、科目、任务、模板与导入、专注与休息会话的写事务，均应先通过 `select id from study_copilot.t_user where id=? for update` 锁定已认证用户。该锁应先于设置、科目、任务、模板或会话锁取得，并保持至提交。任务 5–8 的写入和代表已知用户执行的后台任务遵循同一顺序。注册保留更早的全局请求标识与用户名咨询锁，再获取用户锁。

共享用户锁用于串行化规则变更与会话开始、科目归档与任务创建或迁移及会话开始、最后一个有效科目的检查与其他归档，以及乐观版本校验与并发编辑。仅锁某一设置、科目、任务或会话行不能保护这些跨表约束。所有 HTTP 服务从 `UserContext.requireUserId()` 获取用户身份；内部学习日和结算计算可接收可信后台任务的用户 ID，但每次查询必须限定该用户。不要接受 HTTP 请求体中的资源所有者 ID。

任务 4 新增 V3，不修改 V1、V2。V3 将覆盖全部历史的科目名称约束替换为 `(user_id, lower(btrim(name))) where archived=0` 部分唯一索引。已归档历史科目允许重名，创建、编辑、恢复不得产生有效科目重名。历史有效名称冲突时迁移会明确失败，部署前需处理数据。设置编辑使用当前 `version`，科目编辑、归档、恢复使用科目当前 `version`。归档默认科目同时更新设置并递增版本。存在未完成任务或启用、暂停的重复模板时，归档需选择 `strategy:MIGRATE` 并提供本人有效的 `targetSubjectId`，或选择 `strategy:CANCEL`。已完成或取消的任务引用和历史名称快照保持不变。

学习日按规则 `ZoneId` 使用左闭右开区间 `[start,end)`。Java 时区规则会将不存在的本地时刻向后调整，遇到重复时刻选择较早偏移，因此一天可能为 23 或 25 小时。设置规则变更追加严格递增的 `effective_at` 版本，任何未删除的 `RUNNING` 专注或休息都会阻止变更。结算保留会话采用的规则版本和精确切片时刻；`LearningSlice.seconds()` 返回单片完整秒数，当前结算使用全局整数秒分配保持总时长一致。

V1 不变。V2 演进用户、设置、科目、任务和伙伴状态，并创建刷新会话、版本化学习日规则、引导状态、原子导入批次、重复模板、日程历史、专注会话与切片、幂等记录、奖励、成果领取、账户注销任务。

V6 新增私有头像的可空 `object_key`、`media_type` 和对象键唯一索引，并在 `t_user` 增加昵称与头像独立使用的 `profile_version`；旧附件不开放私有头像读取接口。V1–V5 不变。本轮 V6、V7 均未执行，2026-10-23 的开发未启动应用或开展运行检查。

账户注销同样先锁定用户，在一个事务内取消进行中的专注或休息、不发新奖励、撤销访问与刷新资格，并写入 `t_account_deletion_job`。定时清理器移除本人外部对象、缓存键和关联行，再将身份字段替换为随机审计占位值。缓存仅清理 `${study-copilot.redis-key-prefix}user:{userId}:*`。详细机制和运维流程见 [运维说明](../05-运维部署/后端运维手册.md)，开发期间未执行注销。

用户名去除首尾空格并转小写后全局唯一。V2 遇到历史用户规范化冲突会明确失败，迁移前需核对处理。已有设置为每个用户提供首个学习日规则。外键保护科目、任务、重复模板、导入、规则、切片、奖励的归属关系。列表索引以 `user_id` 开头，到期索引用于结算和注销扫描。幂等记录保留时间不得短于创建后 24 小时。

专注 `mode` 为 `FOCUS`、`SHORT`、`LONG`，`source` 为 `TIMER`、`MANUAL`，终态为 `COMPLETED`、`ENDED_EARLY`、`CANCELLED`。每个用户最多拥有一个未删除的 `RUNNING` 专注或休息。进行中专注的左闭右开有效区间预留至 `scheduled_end_at`；有效秒数至少为 60 的已结算专注使用 `end_at`。休息、丢弃的短区间、软删除补录没有有效区间。相邻区间允许，重叠有效区间由 PostgreSQL 拒绝，包括并发插入。

重复实例按用户、模板、生成学习日唯一；切片和奖励按会话、学习日唯一。奖励账本支持结算服务在事务中执行额度限制，不自行约束多行合计。旧 `t_pet_status.level` 为兼容 V1 保留，不是等级事实来源；一期 A 从 `total_exp` 推导等级。周目标允许为空，不再填入未经用户设置的默认值。

B/C 控制器 `chat`、`journal`、`knowledge`、`milestone`、`mistake`、`notification`、`reminder`、`stat` 仅在 `future-features` 配置下启用；此前 `JournalController` 缺失的导入已修复。基础结构不等于已实现 B/C 行为，一期 A 验收和部署不得启用此配置。

路由由两套默认不启用的配置隔离：`future-features` 管理上述八个 B/C 控制器，`legacy-api` 管理旧任务和旧番茄钟控制器，旧实现已由任务 6–11 的实现替代。2026-10-23 曾进行源码路由边界核对，默认配置仅开放一期 A 路由；这不代表本轮已运行验收。部分注解使用全限定名 `@org.springframework.context.annotation.Profile("legacy-api")`，仅搜索字面量 `@Profile` 会遗漏。

用户创建前，注册请求标识在 `REGISTER` 操作中全局协调。所有应用实例按请求标识、规范化用户名、用户行、刷新会话行的顺序获取 PostgreSQL 咨询锁或行锁。全局规则由应用在 V2 的用户级幂等表之上执行，全部注册入口必须遵循。已使用请求标识对应的请求内容发生任何变化，返回 `IDEMPOTENCY_CONFLICT`。有效重放元数据包含版本、原签发者和非敏感签名密钥指纹。仅在配置、账户、持久化会话仍有效时，才返回原始令牌对；配置轮换、凭据到期或撤销、不支持的旧元数据返回 `TOKEN_REVOKED`，要求重新登录。日常 JWT 轮换时不要一并轮换独立幂等 HMAC 密钥。
