## 一、文档职责与维护关系

本总纲维护产品「为什么做、为谁做、整体做什么、分几步交付」。关联的《一期-A详细需求文档》维护当前交付的页面、操作、字段、计时状态、异常恢复、视觉规范与验收，作为一期-A实施的唯一详细规则来源。

两份文档版本同步为v0.2。范围调整在总纲中记录，同时更新相关实施细则；字段或交互调整只在一期-A文档维护，必要时在总纲摘要说明，避免复制两套完整规则。更新后的原v0.2整合文件作为本次拆分归档，不再作为第三份并行维护的主文档。

当前已确认：**控制台属于一期-A；采用简约、鲸蓝色调与毛玻璃风格；控制台保留完整的学习信息。** 视觉修订不改变A/B/C范围和业务规则。此前水墨概念图停止作为当前视觉依据；本次更新设计规范，新的鲸蓝毛玻璃设计稿尚未生成。

## 二、背景、定位与价值

### 2.1 用户问题

| 问题 | 具体表现 | 产品回应 |
| --- | --- | --- |
| 长期目标与每日行动脱节 | 有备考目标，却不知道今天先做哪件事 | 阶段规划、任务下钻与今日控制台 |
| 专注反馈慢、坚持压力大 | 学习成果难被看见，容易自责或倦怠 | 可靠专注记录、温和反馈与伙伴成长 |
| 数据碎片化 | 手机/电脑/线下学习分散，时长和科目投入难核对 | 跨端恢复、补录、统一时间口径和记录追溯 |
| 缺少复盘与复习 | 每天忙碌但不清楚薄弱点，也缺少下一步建议 | 日志、错题复习、知识点掌握与AI复盘 |

### 2.2 产品定位

融合「阶段规划 + 今日任务 + 专注与伙伴 + 学习记录/统计 + 日志与错题 + AI辅助」的个人长期学习系统。

一句话价值：**让长期学习看得见进度、坚持有陪伴、复盘有依据。**

定位为学习辅助工具，不把计时等同于实际学习质量，不承诺考试成绩提升。优先级为成果可信、开始顺手、信息清晰、反馈温和，再增加装饰与智能能力。

## 三、用户画像与主要场景

### 3.1 典型用户

以备考学生“小林”为例：学习周期长，需要安排多科任务，手机和电脑交替使用；每天可用时间存在波动，可能在教室、图书馆与宿舍切换。也支持语言、编程等自学者，通过自定义目标名称、日期与科目使用，不要求选择固定院校或考试类型。

一期围绕**个人、单一主要目标、单个当前伙伴**设计；伙伴可以切换且保留账号经验。多目标并行、多人协作和组队不进入当前承诺。

### 3.2 关键场景

| 场景 | 用户希望完成 | 首次交付 |
| --- | --- | --- |
| 第一次打开 | 少填资料，得到一项能立即开始的任务 | A：可跳过引导、默认科目/伙伴、模板预览 |
| 每天开始学习 | 一眼看到任务、今日成果和下一段专注 | A：学习控制台与任务快捷开始 |
| 临时离开或换设备 | 原计时和学习成果仍在 | A：唯一运行会话、恢复与幂等结算 |
| 线下学习忘开计时 | 能补齐真实记录，说明奖励差异 | A：补录计时长，不发经验或完成番茄 |
| 任务没做完 | 重新安排而不是面对一堆惩罚提示 | A：待处理、顺延、改期、取消 |
| 日终沉淀 | 写收获、看时间分配、安排明日任务 | B：日志、完整统计和AI复盘 |
| 遇到错题 | 低成本收集，按计划复习 | B：错题与知识点掌握 |
| 需要知识指导 | 问答、梳理思路、得到计划调整建议 | C：AI答疑，修改数据需用户确认 |

## 五、范围边界与A/B/C划分

### 5.1 一期-A：核心闭环与可信控制台

目标：用户第一次能开始、每天愿意打开、每一段成果可恢复且可解释。

必须交付：注册/登录及适用的账号恢复、可跳过引导、模板预览导入、学习控制台、今日任务全流程、可靠专注/休息/提前结束、补录与最小记录列表、五伙伴十级成长、目标倒计时、科目与基础设置、响应式浅深主题、鲸蓝毛玻璃视觉、异常恢复、数据隔离及必要监控备份。

公网开放注册以前必须有可用的邮箱验证/密码找回；若只做受邀内测，可使用明确可达的人工恢复方式。该发布条件由一期-A文档细化，不再把公网用户无法找回账号留到二期。

### 5.2 一期-B：复盘与长期沉淀

交付阶段时间轴与下钻、完整日/周/月/年统计、学习日志与状态打卡、错题本/间隔复习/知识点掌握、基础站内提醒与浏览器提醒、AI日志复盘、个人数据导出。

B复用A的任务、真实专注区间、统一时间切片和经验账本，不重新定义学习日与奖励规则。B的详细需求在实施前单独评审，总纲记录其边界与原有功能基线。

### 5.3 一期-C：视工期交付的增强

AI答疑对话、日志关键词搜索；可以根据进度顺延到二期，不作为A/B核心闭环通过的替代条件。

### 5.4 本轮确认的统计边界

| A控制台必须有 | B完整统计中心 |
| --- | --- |
| 今日已结算时长、完整番茄数、任务完成率 | 独立统计页面，日/周/月/年切换与日期翻页 |
| 本周时长对自定目标的进度 | 周柱状/堆叠统计、月趋势/7日均线 |
| 当前学习日科目投入和占比 | 日内小时分桶、跨周期科目分析 |
| 最近3条记录、查看/补录入口 | 年度热力图与年度汇总 |

这次增加A摘要使用已有任务和专注数据，不扩成完整统计平台。A主导航为「控制台 / 任务 / 专注」；B/C功能交付后再设计入口。

### 5.5 二期及范围外

| 方向 | 后续功能 |
| --- | --- |
| 专注增强 | 全屏沉浸、白噪音、离开提示、中断原因/分心分析、久坐提醒 |
| 游戏化长线 | 成就徽章、连续打卡、满级后机制、赛季/重生、装扮、摸摸/喂食等互动 |
| AI深度 | 周/月复盘、基于进度的阶段计划草稿、错题智能出题 |
| 成绩与目标 | 真题/模拟考成绩、分数趋势、院校与科目目标分 |
| 统计增强 | 环比、最佳时段、情绪与投入关联 |
| 账号/渠道 | 多设备管理、回收站、邮件/微信等额外提醒渠道 |

其中邮箱验证/找回已按公网发布条件提前，不再笼统列为二期。A不做离线新建会话，浏览器关闭后的主动唤醒提醒不作承诺。

## 六、控制台与统一视觉方向

### 6.1 控制台是一期开箱即可使用的工作台

控制台集中回答：现在做什么、今天学了多少、任务完成多少、周目标进度如何、科目投入是否可核对、刚才的学习是否已经保存。

桌面布局为紧凑页眉/目标倒计时、四项指标带、今日任务与快速专注双栏、当日科目投入与最近记录；伙伴精简陪伴。桌面任务摘要最多6条、移动最多3条，完整数量和筛选不因截断而改变。移动端优先显示当前会话和开始入口，其他区域自然纵向排列。

本总纲不复制每项字段和公式；具体数据口径、更新触发、空态、异常与移动端布局以一期-A文档 A.2、A.10 为准。

### 6.2 简约、鲸蓝色调与毛玻璃

页面采用雾白/浅灰蓝底色、克制的鲸蓝强调与半透明磨砂表面，整体清爽、安静、有层次。此处「鲸蓝」是本产品的低饱和深海蓝视觉定义，不表示必须加入鲸鱼插画、海洋场景或海浪动效。主色与可执行Token统一在一期-A文档 A.11 维护。

毛玻璃优先用于导航、顶部工具栏、快速专注等少量重点容器。任务列表、表格、正文和数字使用较高不透明度的干净表面；通过留白、细边框和轻阴影建立层次，保留控制台既有信息密度。背景可用极淡静态鲸蓝柔光，不加入大幅风景、纸纹、印章或复杂纹理。朱红不再作为品牌点缀，成功/警告/错误保留必要语义色。

伙伴采用清爽柔和的简洁插画或轻量立体风格，保留五种伙伴和四阶段的识别，不占据主要操作区域。界面采用清晰中文无衬线字体，数字使用等宽数字，不依赖装饰字体制造氛围。

支持浅色/深色/跟随系统，保持正文对比度、键盘焦点、静音与低动态要求。提供独立的「降低透明度」显示选项；浏览器不支持模糊、设备负载较高或用户关闭透明效果时，回退实色面板，功能和布局保持可用。默认关闭背景动画，不把模糊渲染作为开始学习的前置条件。参数、组件状态、移动端策略及验收以一期-A文档 A.11 为准。

## 七、成功指标与测量方法

所有目标值均为待验证目标，不代表已获得的用户数据；上线先建立基线，再按用户类型和版本观察。

| 指标 | 目标/观察值 | 适用阶段 |
| --- | --- | --- |
| 首次开始效率 | 可用性测试至少4/5用户从注册成功到开始专注≤3分钟 | A |
| 回访开始效率 | 已有科目任务、首页加载完成后≤3次点击开始 | A |
| 数据可信 | 结算、奖励、任务与恢复关键用例全部通过；无重复入账/丢成果 | A |
| 7日/30日留存 | 原始参考目标≥40%/≥20%，上线验证 | A起观察；复盘价值随B增强 |
| 日均完成番茄 | 原始参考目标≥4个；仅计完整TIMER FOCUS | A起观察，不作为强迫学习指标 |
| 日志填写率 | 有有效日志的活跃用户占比≥50%，先建立基线 | B |
| AI复盘使用率/满意度 | 原始参考≥30%/≥70%；满意度为有效反馈中点赞占比，展示样本数 | B |

留存建议：注册所在学习日为D0；D7/D30发生有效学习、任务操作或已上线复盘行为视为相应回访；只打开页面不计有效留存。指标定义需在埋点方案中固定，不能每次汇报更换分母。隐私敏感正文、密码和邮箱不进入行为埋点。

发布前至少5位目标用户进行无人讲解的核心任务测试，记录完成率、耗时和卡点。小样本用于发现问题，不据此宣称整体用户满意度与留存达标。

| 年统计（B） | 年度热力图、点击进入当日记录/日志；档位0、<1h、1–3h、3–5h、≥5h；按实际年份包含365或366天；汇总时长/打卡日/连续日，不因无日志就遗漏有效学习 |
| 日志编辑（B） | 每用户每学习日一篇；Markdown、LaTeX、代码高亮、图片粘贴/拖拽；单图≤5MB，jpg/png/webp；本地与服务端30秒自动保存，离开保护未保存内容；版本冲突不能静默覆盖 |
| 日志打卡（B） | 精力/情绪单选、核心突破、科目自动时长、最多3项明日微计划；保存幂等生成次学习日任务，保留映射避免每次保存重复创建；手动时长修正作为主观备注与自动值并列，不反向改写A事实账本 |
| 日历归档/搜索（B/C） | 日历日期情绪点、查看当日日志/任务/专注；关键词搜索C，查询失败与无匹配分开，支持公式代码在移动端阅读 |
| 错题收集（B） | 日志/专注结束/快捷入口；科目+图片即可保存，标题/知识点/文字公式/错因/解析可后补；错因粗心/概念不清/不会做/计算失误；移动拍照优先，权限拒绝仍可选相册 |
| 错题复习（B） | 1/2/4/7/15/30天间隔；已会进入下阶段、模糊保持间隔、不会回到1天；到期队列为next_review_date≤当前学习日；逐题先看题再看解析自评；评审时明确每个间隔以何次实际复习日为基准，保持幂等不重扣 |
| 知识点（B） | 科目知识点树、预置模板导入、自建；未学/学习中/已掌握；错题与阶段可关联，进度可参考但不能把某题通过直接等同于整个知识点掌握 |
| AI日志复盘（B） | 用户主动点击；使用当日任务、日志正文最多4000字、科目投入、情绪、突破与近7日平均；输出高光/分配评估/≤3条可执行建议；落库、重生成、点赞踩；每日最多3次；说明首次生成是否计次数及失败是否退还，实施前确定 |
| AI答疑（C） | 桌面侧栏、移动全屏抽屉；专业鼓励简洁、支持公式与Markdown、持久会话，默认最近10轮上下文；计划调整先给建议，用户明确确认后再写入，不自动改任务 |
| AI隐私与容错（B起） | 后端代理模型Key；首次显式同意第三方处理、设置中可关闭；限流/超时/失败友好处理；系统提示和用户内容隔离只是防护的一部分，不能宣称绝对防注入；具体模型与每日对话额度实施前确认 |
| 提醒（B） | 开始学习08:30、错题复习20:00、日志22:00为可修改建议；分类开关、自定时间、完成相应行为后不重复提醒；站内+已打开页面可用的浏览器通知，不承诺关页唤醒；文案温和无惩罚 |
| 导出（B） | 日志Markdown按日期打包，图片随包或可离线读取；其余JSON含版本/时区和引用关系；导出本人数据，失败可重试，不依赖AI同意 |

B/C尚需确认的实施问题：完整统计在时区规则切换的过渡期如何呈现、日志主观修正如何标注、错题间隔精确定义、AI配额失败退还与报告版本、阶段日期和排序冲突处理。这些事项需要在实施前补齐，不能由前后端各自猜测。

## 九、技术方向与质量底线

| 层 | 既定方向 | 范围 |
| --- | --- | --- |
| 前端 | Vue 3、Vite、Pinia、Vue Router；Element Plus/Tailwind可主题化 | A起，采用简约鲸蓝毛玻璃规范 |
| 后端/认证 | Spring Boot 3.x、Spring Security、Access/Refresh JWT | A起 |

核心约束：统一UTC存储和用户学习日；单账号唯一运行会话；结算/奖励幂等与事务一致；跨日切片、补录不重叠；所有业务数据按用户隔离；Markdown与上传按类型/大小/归属校验；敏感配置不入仓库；日志/指标可追溯且脱敏。

性能和恢复目标以一期-A文档 A.14 为当前基线；备份建议每日、保留7天并演练恢复。A.16共54条验收用例定义发布门槛，尚未执行产品代码测试。旧v0.2的15表SQL保留于整合归档，不能直接宣称满足更新规则；研发需依据A.17形成最终schema/API/迁移设计。

## 十、迭代路线与风险

### 10.1 按质量推进的交付顺序

| 阶段 | 结果 | 门槛 |
| --- | --- | --- |
| A 核心闭环 | 能注册、安排、开始、恢复、结算、查记录；控制台和伙伴可日常使用 | 当前实施文档关键验收与可用性测试通过 |
| B 复盘沉淀 | 阶段规划、完整统计、日志、错题复习、提醒、AI复盘和导出 | 复用A统一口径；各模块先补详细验收再实现 |
| C 收尾增强 | AI问答与日志搜索 | 根据工期决定是否一期交付，不挤占A/B质量 |
| 二期 | 沉浸增强、长期游戏化、AI深度、成绩与统计增强 | 基于真实行为与反馈排序，避免预先堆功能 |

具体排期在团队规模、现有实现与美术资源明确后给出，本总纲不预设虚构工期。A内部开发包和演示完成定义在详细文档A.18维护。

### 10.2 风险与应对

| 风险 | 应对 |
| --- | --- |
| 一期功能过多，基础体验欠打磨 | A/B/C明确分界，A控制台信息丰富但复用已有数据；按验收门槛发布 |
| 透明面板对比度不足或模糊效果拖慢设备 | 控制背景与透明度，内容区提高不透明度；提供降低透明度与不支持时的纯色降级；浅深主题逐状态检查 |
| 五宠四阶段美术量较大 | 允许叠加配饰，保持阶段可辨识；静音/低动态必须被尊重 |
| 多设备/断网造成成果不一致 | 服务端唯一会话、持久化恢复、事务结算、请求幂等与数据版本 |
| 奖励导向变成刷时长 | 不把计时等同学习质量，补录不发奖，部分奖励与日额度可解释，不惩罚缺席 |
| 长期满级缺少目标 | 十级阈值先沿原基线，二期按观察补徽章/赛季；调参版本化 |
| AI成本、稳定性和隐私 | 显式同意、后端代理、限流、失败降级；不影响基础学习功能 |
| 两份文档重复维护 | 总纲管范围，详细文档管A实施；整合文件归档，变更同步版本 |
