## 阅读说明与必要背景

Study Copilot 是面向考研及长期自学者的响应式Web学习管理系统。整体价值是「看得见进度、坚持有陪伴、复盘有依据」；A先打通注册/引导→控制台看到今日任务→开始专注→可靠结算→获得温和反馈→明天继续的闭环。

典型用户手机与电脑交替使用，常见场景为上午安排任务、白天反复专注、临时中断后恢复、线下学习后补录。A可以独立使用，不依赖B的阶段规划/日志/完整统计或C的AI对话。

已确认的视觉方向为**简约、鲸蓝色调与毛玻璃**：雾白/浅灰蓝背景、克制的深海蓝强调、少量半透明磨砂表面与轻阴影。控制台继续包含四项指标、任务摘要、快速专注、伙伴、当日科目投入与最近记录；本文件 A.2 与 A.11 是当前设计交付依据。此前水墨概念图停止作为当前视觉依据，本次未生成新设计图，也不代表已完成前端实现。

技术上下文：后端Spring Boot 3.x、Spring Security/JWT、MyBatis-Plus/MySQL 8、Redis；前端Vue 3、Vite、Pinia、Vue Router，UI可用Element Plus与Tailwind实现鲸蓝毛玻璃主题。Markdown、AI和完整ECharts统计按后续范围交付。UTC存时间，用户时区与学习日起点决定统计归属。技术约束和最小接口清单见 A.17，不要求读旧版整合文件才能理解A。

## A.0 产品目标与交付边界

### A.0.1 一期-A 要交付的感受

用户打开系统，能立即看懂今天先做什么；一次操作就能继续学习；临时离开、刷新、断网不会轻易丢掉学习成果；结束后知道学了多久、任务有没有完成、宠物获得了什么，再自由决定休息或继续。

优先级顺序：**成果可信 > 开始顺手 > 页面易读 > 反馈温和 > 装饰丰富**。体验门槛不能用增加动画、页面或 AI 功能替代。

### A.0.2 范围清单

| 必须交付 | A 阶段的完成定义 | 依赖/边界 |
| --- | --- | --- |
| 注册、登录、会话恢复 | 成功进入系统；错误可理解；登录过期后能回来继续 | 公网开放注册前必须有账号找回，见 A.3 |
| 新手引导、模板 | 可跳过；可预览；不重复生成任务；能开始第一段学习 | 不要求先填完整目标、阶段或头像 |
| 今日任务 | 快速添加、完成/撤销、排序、改期、顺延、取消、简单子任务和重复任务 | 阶段编辑、完整规划页属于 B |
| 专注计时 | 开始、到时结算、提前结束、休息、恢复、跨端互斥 | A 不做暂停、白噪音、全屏模式 |
| 补录 | 能录入真实线下学习；查重；能修正或删除 | 只计时长，不发经验、不计完成番茄 |
| 萌宠 | 五选一、切换、累计经验、十级与四阶段形态、反馈设置 | 配饰叠加可实现中间形态；不要求商店/投喂 |
| 控制台、倒计时、设置 | 今日任务/专注入口、四项指标、今日科目投入、最近记录、伙伴成长、浅深主题与移动端适配 | 控制台明确属于 A；详细统计中心属于 B |
| 最小专注记录列表 | 能解释首页数字，查看来源，修正补录 | 日/周/月/年图表、完整导出仍属于 B |

其中「专注记录列表」是 A 的必要补充：没有可追溯记录，用户无法判断计时是否保存成功，首页数字也无法核对。

**A 不展示占位导航**：AI、日志、错题、完整统计、规划中心在功能可用前不进入主导航；完成任务后 A 的引导为「休息一下 / 再安排一件事」，不跳转到尚未上线的日志页。

### A.0.3 指标与口径

下表均为待验证目标，不能视为已经证明的效果。先以可用性测试和核心行为观察判断，再参考留存。

| 指标 | 计算口径 | A 的目标/用途 |
| --- | --- | --- |
| 首次开始效率 | 注册成功至首个专注开始成功，另记用户实际操作时间 | 测试用户至少 4/5 能在 3 分钟内完成，无人指导 |
| 回访开始效率 | 已登录、首页加载完成起，到开始接口确认；已有科目任务 | ≤3 次点击；任务上直接开始通常 1 次 |
| 引导退出恢复 | 中断引导后再次打开，已确认内容恢复 | 核心测试全部通过 |
| 计时成果一致性 | 相同专注的记录、时长、经验是否一致且只入账一次 | 自动验收用例中 100% 一致；出现不一致阻断发布 |
| 数据恢复成功 | 刷新/断网/设备切换后找回同一个进行中或已完成会话 | 核心场景全部通过，不将心跳断开判为放弃 |
| 7 日留存 | 注册日为 D0，在 D7 学习日发生有效学习/任务/复盘行为的用户比例 | 先记录基线；原 ≥40% 作为后续验证目标 |

## A.1 统一概念与规则

| 名称 | 唯一定义 |
| --- | --- |
| 学习日 | 按用户时区与一天起点归属的日期。默认 Asia/Shanghai、00:00；起点 04:00 时 03:00 属于前一个学习日 |
| 今日任务 | 当前学习日计划完成的顶层任务；包含取消、完成、未完成三种业务结果，展示分区不同 |
| 一次专注 | 一条带科目、可选任务、服务端起止时间的专注会话，不等同于完成了任务 |
| 完成番茄 | TIMER 来源、FOCUS 模式、实际走到计划结束时刻的会话；提前结束/补录/休息均不计入 |
| 有效学习时长 | 已结算专注或有效补录的时间区间之和；排除休息、未结算预估值及不足 60 秒的提前结束 |
| 任务完成 | 用户主动勾选，或所有有效子任务完成后父任务自动完成；专注结束不自动完成任务 |
| 本周 | 用户设置时区下，周一开始的七个学习日；A 不提供近七天/自然周切换 |
| 唯一运行会话 | 同一账号最多一个 RUNNING 会话，专注与休息共同互斥；多个页面展示同一个会话 |

**日期显示**：00:00 起点时可用「今天」；非零起点时首页、任务、记录写明「今日学习日：10 月 22 日，04:00–次日 04:00」。考试倒计时按当地日历日期计算，不减四小时。

**时长显示**：底层保存秒或毫秒；单条记录显示分秒；汇总先求和再按分钟向下取整，不将每条先取整后相加。图表和经验不得读取前端显示文本计算。

**设置生效**：时区与一天起点仅可在没有运行会话时更改；从下一个旧规则学习日边界生效，界面提前显示具体时刻。该时刻开启新统计规则版本；历史日志日期和已入账分桶保持原样，不悄悄改写。生效时正在运行的会话仍按开始时的版本拆分与计奖。过渡期当日可能不足或超过 24 小时，记录页注明，不伪装成固定 24 小时。

## A.2 信息架构与页面契约

### A.2.1 导航与入口

| 页面 | 桌面端 | 移动端 | 唯一主操作 |
| --- | --- | --- | --- |
| 控制台 | 左侧主导航，默认首页 | 底部「控制台」 | 有运行会话：继续专注；否则：当前选中任务的开始 |
| 任务 | 左侧主导航 | 底部「任务」 | 添加任务 |
| 专注 | 左侧主导航 | 底部「专注」 | 开始/结束当前会话 |
| 专注记录 | 专注页的二级入口 | 专注页的二级入口 | 补录学习 |
| 伙伴 | 首页宠物卡进入 | 首页宠物卡进入 | 查看成长/更换伙伴 |
| 设置 | 头像菜单 | 顶部头像菜单 | 按分组保存 |

桌面 ≥1024px 使用侧栏；768–1023px 收起侧栏；<768px 使用三项底部导航。运行中计时条在非专注页面常驻，移动端位于底部导航上方，不遮挡输入框、表单按钮与安全区。

### A.2.2 控制台信息优先级

控制台以「马上能做什么 + 今日成果 + 本周目标 + 可追溯记录」为信息主线。桌面采用紧凑页眉、四项指标、任务/快速专注双栏、科目投入/最近记录；移动端优先保留当前会话和开始入口，按 A.2.5 重排。真实无数据时显示空态，不填充演示成果。

| 首页情境 | 主文案/主操作 | 附加规则 |
| --- | --- | --- |
| 首次进入、无任务 | 「从一件小事开始」/添加任务；次操作「直接专注」 | 不强制填目标或导入模板 |
| 有待办 | 优先展示用户手动选中项，否则按手动顺序取第一项 | 不按所谓智能推荐每天重排 |
| 正在专注 | 当前科目、任务、倒计时/继续专注 | 任务区可查看，不推荐切换到别的任务计时 |
| 全部完成且至少一项 | 「今天安排的任务已完成」/休息一下 | 可添加下一件；庆祝每天首次达成时出现一次 |
| 有历史待处理 | 折叠显示「有 N 件任务可重新安排」 | 不自动塞进今日列表，不用红色堆叠 |
| 今日暂无学习记录 | 「今天还没有记录，从 15 分钟开始也可以」 | 不显示连续中断或倒退警告 |
| 离开多日后回来 | 「欢迎回来，先做一件小事吧」 | 宠物不生病、不掉级，不弹出一串欠账 |

### A.2.3 全局交互规范

- 一个卡片只突出一个主按钮；次要操作放更多菜单。删除/取消/停止属于次要操作，不与开始按钮同等抢眼。
- 所有异步写入按钮阻止连续提交。列表乐观更新要有失败回滚和重试；计时开始、计时结算、经验奖励必须等待服务端确认后才显示成功。
- 保存成功用轻提示，不用确认弹窗。确认仅用于会丢失成果、影响多条数据或不可逆操作；可撤销的轻量操作优先提供 5 秒撤销。
- 从任务详情返回恢复筛选和滚动位置。表单关闭再进入保留尚未提交内容，退出登录后清理对应账号的本地敏感草稿。
- 表单错误出现在对应字段附近，保留其他输入。移动端自动滚动到首个错误，但不反复抢夺焦点。

### A.2.4 一期-A 控制台信息结构（本轮确认）

**控制台属于一期-A，且是登录后的默认首页。**「今天」「首页」「今日概览」在早期稿中均指同一入口，对外导航名称统一为「控制台」。桌面与移动端均使用「控制台 / 任务 / 专注」三项主导航。增加控制台摘要不意味着提前交付 B 的完整统计中心。

桌面控制台采用「紧凑页眉 + 四项核心指标 + 今日任务/专注操作双栏 + 科目投入/最近记录」结构。信息量需足够支持一天的学习安排，减少大标语和装饰画占用；保持一个最突出的主动作「开始专注」，有运行会话时替换为「继续专注」。

| 区域 | 一期-A 必须展示 | 操作与边界 |
| --- | --- | --- |
| 页眉与目标 | 控制台标题、当前学习日、简短问候、可选目标剩余天数 | 目标可编辑；标注自定日期；未设日期显示设置入口 |
| 今日专注 | 已结算学习时长，运行中估计另行标注 | 点击打开当日专注记录，不将预估冒充到账 |
| 完成番茄 | 当日完整 TIMER FOCUS 数 | 与补录、提前结束和休息区分 |
| 今日任务 | 已完成/有效顶层任务总数及百分比 | 无任务显示暂无计划；点击任务区域，沿用同一日期筛选 |
| 本周目标 | 已完成时长/自定目标、进度百分比 | 未设置时显示设置入口；超目标保留实际百分比，进度条封顶 |
| 今日任务列表 | 标题、状态、科目、预计番茄、更多菜单 | 默认展示至多 6 条顶层任务；总数和筛选基于完整集合，不受截断影响 |
| 下一段专注 | 选中任务、科目、时长、主按钮 | 与任务页/专注页选中项一致；不另开一套计时逻辑 |
| 学习伙伴 | 当前伙伴、等级、经验进度、简短反馈 | 精简插画；可进入成长详情/更换伙伴，不遮挡计时操作 |
| 今日科目投入 | 各科有效分钟、占比、轻量水平条 | 只展示当前学习日摘要，点击科目进入记录筛选；没有周/月/年切换 |
| 最近专注 | 最近 3 条已结算学习记录，时间、科目、时长、结果、来源 | 默认当前学习日；查看记录、补录学习可用；不是只列完整番茄 |
| 待重新安排 | 历史未完成任务数量与折叠入口 | 不自动插入今日任务；顺延遵守重复实例冲突规则 |

今日任务筛选为「全部 / 待完成 / 已完成」；全部包含有效 TODO 与 DONE，取消项仅在任务详情/任务管理的相应筛选查看，不混入默认总数。全部列表先按用户手动顺序展示未完成项，再展示已完成项；每组保持原顺序。超过 6 项显示「查看全部 N 项」，取消筛选回到默认后保留选中项。移动端默认展示至多 3 项，保留同一完整计数。

### A.2.5 控制台布局、密度与响应式

- **桌面 ≥1024px**：固定侧栏约 168–208px；页眉约 96–144px；四项指标为一条整齐的信息带。中间任务区约占可用宽度 60%–68%，右侧为快速专注与精简伙伴区；下方放科目投入与最近记录。不为填满页面加入无关模块。
- **1440×1024 设计基准**：正常浏览器缩放下，首屏能看见四项指标、任务列表、开始/继续按钮、科目投入与最近记录的标题及至少部分内容；允许自然纵向滚动看完整数据，不缩小正文硬塞进一屏。装饰背景、模糊面板与大标语不能挤掉主要功能。
- **768–1023px**：侧栏收为图标栏；指标可为 2×2；快速专注紧贴任务区域，伙伴移到低优先级区域。避免两栏挤到任务标题不可读。
- **移动 <768px**：按「日期与目标 → 当前会话/快速开始 → 核心指标 → 今日任务 → 本周目标 → 科目投入 → 最近记录 → 伙伴」顺序单列；指标区优先保留今日时长、番茄数与任务完成，周目标独立展示。记录使用紧凑列表而非宽表格。
- 同一指标只在合适位置完整出现一次。桌面已在指标带展示周目标，下方不再复制一张同值卡；移动拆行属于同一组件重新排布。密度靠缩短装饰区和合理分组实现，正文不低于可访问性要求。
- 主内容使用雾白/浅灰蓝底与高不透明度内容表面；任务、数字和按钮所在区域保留稳定对比度。使用留白、字重、细分隔线分组，避免每行一个厚卡片、卡片套卡片或重阴影。

### A.2.6 控制台联动、空态与异常

| 触发 | 控制台必须发生的变化 |
| --- | --- |
| 选择另一项待完成任务 | 快速专注同步任务、科目与估计；仍采用已确认时长，不立即启动 |
| 存在运行会话 | 显示该会话与剩余时间；主操作为继续；其他任务不得创建并行会话 |
| 完成/提前结束专注 | 按最终结果刷新今日时长、番茄数、周目标、科目投入、最近记录和经验；不自动完成任务 |
| 勾选/撤销任务 | 更新列表和任务指标；不产生专注分钟或经验 |
| 补录/修正/删除补录 | 更新时长、周目标、科目投入和最近记录；完整番茄数与经验不变 |
| 切换到新学习日 | 重新获取当前日期数据与重复实例；当前运行会话仍恢复原记录 |
| 目标/科目/主题更新 | 显示最新配置，遵守时区/日起点延迟生效和历史快照规则 |
| 某模块加载失败 | 该模块局部重试；其他已成功区域可用；不能显示假 0 或清空已确认数字 |
| 首次无记录 | 今日时长 0、完整番茄 0；科目区显示暂无学习记录、提供开始入口；最近记录不填演示数据 |
| 未设置周目标/目标日期 | 显示具体设置入口；不擅自设置 20/35 小时或考试日期 |

控制台支持首次进入、返回前台和服务端同步事件刷新。旧请求结果不能覆盖新结算版本；若只部分模块刷新成功，保留各自已确认数据，不把全页清空为骨架。运行中预估与最终入账字段分开命名。

### A.2.7 今日科目投入与最近记录的口径

1. 科目投入读取当日有效时间切片，包含完整计时、≥60 秒提前结束、有效补录，排除休息与未结算预估。各科秒数之和必须等于当日已结算总秒数。
2. 百分比以秒为单位计算，不先把每条记录截成整数分钟再算。显示保留 1 位小数或去掉无意义的 .0；四舍五入造成总和 99.9%/100.1% 可在提示中解释，不篡改真实数据。
3. 展示科目名、数值和条形长度，不能只靠颜色；主图最多 5 门，超出项合并为「其他 N 门」且可展开。归档科目的历史投入仍可显示，名称归属沿用统一历史记录策略。
4. 点击科目在同一学习日记录页筛选；无数据时不绘制空圆环或 0/0 占比。
5. 最近记录按真实结束时刻倒序，当前学习日中跨日起点的记录显示其当日切片并可查看完整会话。提前结束写明「提前结束」，补录写明「补录」，不得统一标为完成番茄。
6. 列表显示至多 3 条只是摘要；补录按钮不要求先有历史记录。记录到达与删除后的空位由当前查询结果补齐。


## A.3 注册、登录与账号恢复

### A.3.1 表单与验证

| 字段/动作 | 规则 | 失败反馈 |
| --- | --- | --- |
| 用户名 | 4–30 位字母、数字、下划线；去首尾空格；大小写不区分占用 | 「用户名为 4–30 位字母、数字或下划线」；提交时检查占用 |
| 密码 | 8–64 字符且 UTF-8 编码不超过 72 字节；允许粘贴、空格、中文与密码管理器；提供显示切换 | 超过字节上限明确提示缩短，不静默截断，见 A.17 |
| 邮箱 | 公网版必填；内测可选 | 验证失败保留输入、展示重新发送入口 |
| 登录 | 支持用户名；公网版另支持已验证邮箱 | 统一「账号或密码不正确」，不暴露是否注册 |
| 重复点击 | 同一注册请求只创建一个用户及一套初始化数据 | 请求处理中显示「正在创建账号…」 |
| 登录失败限流 | 按账号与来源做渐进退避，不因固定少量失败让攻击者长时间锁死他人账号 | 显示剩余等待时间；成功后清除相应失败计数 |

公网发布要求：可验证邮箱、忘记密码、重置完成后其他刷新令牌失效。重置邮件申请统一反馈「如果该邮箱已注册，我们会发送重置说明」，令牌一次性、30 分钟失效、限制重复发送。若没有邮件能力，A 只做受邀内测，并明确提供人工账号恢复入口，不把不可恢复的注册系统面向公开用户上线。

### A.3.2 会话与成果保护

- 注册成功建立会话，进入引导；引导不能拦截已恢复的运行会话。
- Access Token 过期先尝试一次串行刷新；多个失败请求共用刷新结果。刷新成功重试原请求时复用幂等键，防止重复任务/奖励。
- 刷新失败显示登录入口，并保留当前操作草稿；重新登录后返回原路由。服务端会话计时继续，不能因登录页出现就停止。
- 退出登录有运行会话时提示「退出后计时会继续；再次登录可以恢复」，允许退出或返回。共享设备退出后清理用户缓存。
- 登录时先查询当前会话和未确认结算结果，再决定首页默认状态，避免一瞬间出现新的开始按钮。

## A.4 新手引导与模板

### A.4.1 两条可完成路径

**快速使用**：注册成功 →「先开始学习」→ 默认伙伴 + 默认科目进入首页 → 添加一件任务或直接专注。科目/时长提供可见默认值，允许跳过考试日期、日可用时间与模板。跳过不是未完成错误，设置页提供「继续完善计划」。

**完整引导**：伙伴 → 日期与可用时间 → 科目 → 模板预览确认 → 首页。每步有「上一步」「稍后设置」，退出后恢复已保存步骤。预计一至三分钟，实际耗时通过测试验证。

| 步骤 | 默认与限制 | 体验细节 |
| --- | --- | --- |
| 伙伴 | 默认粉粉喵；五只都可选，成长属性相同 | 展示幼年和终极预览，注明成长来自专注，不暗示付费 |
| 日期与可用时间 | 日期可留空；可用时间可不设，不预填 6–8 小时高强度目标 | 目标名称可自定义；日期不得在过去，支持今天 |
| 科目 | 考研默认高数/英语/政治/专业课；允许改名、归档、新增 | 至少保留一门有效科目；不限定为考研四科 |
| 模板 | 默认「我自己安排」；基础/强化/冲刺/全程可预览 | 不默认勾选导入；示例内容标注为可调整，不承诺个性化适配 |

未设置日期：首页显示「设置学习目标」的小入口，不出现假考试日期。用户手填日期标记「自定日期」，一期不默认宣称某天是官方考试日期。倒计时当天显示「目标日到了」，过期显示「设置下一阶段目标」，不显示负数。

### A.4.2 模板生成规则

1. 预览明确展示：阶段名称与日期、未来七个学习日要生成的任务数量、今日任务、预计专注时间、导入后可编辑。A 提供只读阶段摘要，B 才提供阶段编辑页面。
2. 时间范围根据当前学习日和目标日期调整；日期倒置、剩余时间不足以容纳所选阶段时，说明原因并切换较短模板，不能静默压缩成不现实安排。
3. A 只生成未来七个学习日的可执行任务；更远阶段只存阶段框架和模板版本，不预生成几百条待办。后续任务由用户在 A 手动安排、或在 B 的规划流程中生成，A 不承诺全程自动排课。
4. 今日默认至多三项模板任务，可主动增加。用户填写可用时间时，默认安排预计专注时间不超过可用时间的 70%，预留休息与临时事项。预计番茄按导入时的默认专注时长换算，后续更改时长不重写历史估计。
5. 每项任务可取消勾选、修改标题/科目/预计番茄；先预览再一次确认。确认文案为「导入 N 项任务」，不使用模糊的「完成」。
6. 一次导入是原子操作，具备 request_id 和 import_batch_id；超时重试返回同一批结果，刷新不重复导入。已有任务时默认只追加预览中选中的新任务，不覆盖用户内容。
7. 同一模板同一日期再次导入时标出已导入项，默认不选；同标题不能作为唯一去重条件，必须依据模板条目标识和目标日期。用户手动新建同名任务仍合法。
8. 完成页只强调「先做这件事」，并提供任务开始按钮，不再串联弹出通知授权、宠物改名和目标设置。

**验收**：跳过引导也有可用科目和伙伴；关闭页面后继续引导内容不丢；模拟导入响应超时后重试只产生一个批次；模板七日内容不会全部变成今日任务。

## A.5 今日任务详细需求

### A.5.1 创建与编辑

| 字段 | 必填/默认 | 约束 |
| --- | --- | --- |
| 标题 | 必填 | 去首尾空格，1–200 字符；空标题不能提交 |
| 科目 | 快速创建可暂不选 | 与任务关联开始前必须补齐；优先继承明确的当前筛选科目，不猜测标题含义 |
| 计划日期 | 默认当前学习日 | 可选未来或不设日期；过去日期进入待处理区 |
| 优先级 | 默认中 | 高/中/低，颜色外另有文字/图标说明 |
| 预计番茄 | 可选 | 整数 1–16；是估计，不限制实际专注次数；超出日可用时间时温和提示仍可保存 |
| 子任务 | 可选 | 只一层，建议单父任务不超过 20 项，标题限制同上 |
| 重复规则 | 默认不重复 | 每天、指定周几、周一至周五；不按法定调休日历计算 |

- 快速添加输入标题按 Enter 保存；中文输入法组合期间按 Enter 不触发提交。标题保存后输入框继续聚焦，方便连续录入。
- `#科目` 可选快捷语法，输入 `#` 展示已有科目候选；选择后显示科目标签。无法匹配时保留原文并提示选择科目，不自动创建科目、不吞掉标题文字。
- 新增任务立即出现在当前筛选匹配的列表中并标记「保存中」；失败保留输入、撤销未确认条目。网络未确认的任务不能直接启动服务端专注。
- 更改任务日期/科目不会回写已完成专注的归属。运行会话关联的任务不能在计时中删除或换科目；可编辑标题，当前会话仍展示开始时快照并提示记录以开始时信息为准。

### A.5.2 列表与状态

| 状态 | 操作 | 对统计的影响 |
| --- | --- | --- |
| TODO 未完成 | 开始、编辑、改期、取消、删除 | 进入对应日期的有效计划分母 |
| DONE 已完成 | 撤销完成、查看记录 | 进入计划分子；不额外发放经验 |
| CANCELLED 已取消 | 恢复为未完成、改期 | 不进入任务完成率分子或分母，保留取消记录 |
| 已删除 | 5 秒内撤销；过后 A 不提供回收站页面 | 不计计划，已结算专注保留任务快照 |

状态只表达业务结果；「进行专注中」是运行会话标识，不新增一个容易卡住的任务状态。完成后移到可折叠的已完成区，保存成功后才计入完成数。

默认按用户手动排序；优先级是标签，不自动覆盖手动顺序。支持拖拽和菜单「上移/下移」，移动端有足够手柄区域。排序在多设备使用版本校验，冲突时载入最新顺序并给出提示，不随机合并。

### A.5.3 父子任务

- 子任务继承父任务科目、计划日期和阶段；不单独设重复规则。父任务或子任务都可以关联专注，但同一会话只关联其中一个。
- 所有未取消子任务完成，父任务自动 DONE。勾选父任务时仍有未完成子任务，提示「同时完成剩余 N 项？」；确认后一次更新，取消则保持原样。
- 撤销一个子任务，父任务变为 TODO；给已完成父任务新增未完成子任务，同样重开父任务并提示。
- 全部子任务取消时不自动判定父任务完成；父任务回到可手动处理状态。取消父任务同时取消未完成子项，恢复时还原取消前状态；已完成子项保留已完成。
- 今日任务完成率只统计顶层任务，避免父子重复计数。父任务实际时长为直接关联自身及子任务记录的去重合计；预计番茄默认取子任务估计总和，不再与父级估计相加。

### A.5.4 重复任务与顺延

- 重复模板与当日实例分开。唯一约束 `(user_id, repeat_template_id, learning_date)`；定时任务和首次访问补偿生成共用同一幂等逻辑。
- 按用户学习日边界生成当日实例，不固定服务端 00:00。服务暂不可用或用户多日未登录时，只补生成当前学习日，跳过期间不积累几百个历史待办；明确标记「离开期间未生成重复待办」。
- 修改可选「仅这一次 / 这次及以后」；后者改变模板及尚未开始的未来实例，保留过去日期和已完成实例。停用模板不删除历史记录，已经出现的今日实例由用户决定是否取消。
- 未完成旧任务进入折叠待处理区；用户选择顺延/改期才改 `target_date`，保留 `original_target_date` 与调度历史。A 的今日完成率是当前计划口径，不宣称为历史执行准确率。
- 批量顺延前展示数量和预览，成功后可一次撤销本次批次；同一重复模板今天已有实例时，不再把昨天实例并入今天，提示选择「保留今日实例并取消旧项 / 分别保留」。默认不自动合并或删除。
- 一键全部顺延只作用于当前筛选下已明确选中的任务，不包括用户看不到的任务；给出数量和日期，防止一次带来大量任务压力。

### A.5.5 关键验收

1. 今日没有任务时也能直接专注；缺科目任务点击开始后只补选科目，确认后开始，不进入多级编辑页。
2. 完成一个番茄不自动勾选任务，结束卡提供用户主动完成入口。
3. 取消/改期/顺延不删除已经获得的学习时间和经验；任务删除后专注记录仍能解释其原始标题。
4. 父任务加子任务不能使一天任务完成率重复计算；0 个有效计划时显示「暂无计划」，不用 0/0 或虚构 100%。
5. 两台设备同时点击同一个任务，任务更新不会重复创建专注或重复发奖。

## A.6 专注计时：开始、结束与休息

### A.6.1 开始前

专注页准备态只要求：**科目、时长**；任务可选。默认 25 分钟，提供 15/25/45/60 分钟快捷项和 15–90 分钟整数自定义；上次成功使用的时长可记住。任务已有关联科目时自动带入，确认的科目才可持久化为用户默认。

从首页任务的「开始」按钮进入：科目齐全、无运行会话、使用上次时长时，直接发起开始并进入计时页；科目缺失时用一个简短选择面板补齐后开始。用户可在准备态改时长，不强制每次弹确认。

开始请求提交后按钮为「正在开始…」，服务端确认 `session_id/start_at/scheduled_end_at/server_now` 后才进入正式倒计时。超时显示「正在确认是否已开始」，先查询当前会话；确认不存在后才能用同一幂等键重试，不能盲目创建第二段。

运行时保留科目、任务、剩余时间和「结束本次」。默认无暂停：有事可提前结束，回来开始新一段。设置、引导和帮助必须使用同一说明，不用隐藏暂停制造误解。

### A.6.2 状态与允许动作

| 状态 | 页面显示 | 允许动作 | 服务端规则 |
| --- | --- | --- | --- |
| READY 准备 | 科目/任务/时长 | 开始、修改设置 | 无运行会话 |
| STARTING 确认开始中 | 进度提示 | 查询恢复、返回查看 | 同一请求只创建一条 |
| FOCUS_RUNNING 专注中 | 倒计时、陪读宠物 | 查看其他页面、提前结束 | 账号内唯一 RUNNING；不因断开连接停止 |
| SETTLING 核对结算中 | 「本段已到时，正在保存」 | 查询结果、离开页面 | 到时不继续累计超时分钟 |
| FOCUS_COMPLETED 已完成 | 单次成果卡 | 休息、继续、完成任务、关闭 | 结果不可重复发奖 |
| FOCUS_ENDED 提前结束 | 已记录时长与奖励说明 | 新开一段、查看记录 | 属于结束结果，不计完成番茄 |
| BREAK_RUNNING 休息中 | 休息倒计时 | 提前结束休息、离开页面 | 不计学习时间、不发经验 |
| BREAK_COMPLETED 休息结束 | 「休息结束，准备好再开始」 | 手动开始下一次 | 不自动启动学习 |

`STARTING/SETTLING` 是界面与请求状态，数据库只需明确会话的 RUNNING/COMPLETED/ABANDONED 及结束类型，不要求把每个 UI 状态建成业务状态。

### A.6.3 到时完成

1. 只有服务端时间达到 `scheduled_end_at` 才能 COMPLETED。取消原文「达到 95% 即算完成」规则，避免未到时就领奖。客户端早到的请求返回仍在运行以及剩余时间。
2. 到时后服务端完成入账，不依赖浏览器保持前台：后台到期扫描和开始/恢复/结束请求中的补偿结算共用一套逻辑。有效区间最多到计划结束时刻，不能因两小时后重开页面就多计两小时。
3. 结算同时写专注结果、经验流水和宠物累计经验/等级；同一事务提交。汇总缓存可异步刷新，但首页先展示服务端返回的确定值，避免奖励成功、时长短暂变少。
4. 成果卡展示：科目/任务、本次实际时长、经验实际到账值、今日已结算总时长。主操作「休息 5 分钟」，次操作「继续专注」，另提供「任务已完成」和「先到这里」。
5. 选择任务已完成需要独立成功的任务更新；失败保留专注结算结果，提示稍后重试。不可让任务接口失败导致已完成专注回滚。
6. 成果卡可随时关闭，之后能从专注记录找回；跨设备只允许一个页面领取强反馈展示权，其他页面同步更新数字。未看过的旧结果回访时最多汇总提示一次，不连弹多张卡。
7. 不将用户离开页面等同于分心，不宣称计时可以验证真实学习质量。

### A.6.4 提前结束与部分记录

点击「结束本次」出现底部面板/对话框，显示已专注时间，提供「继续专注」和确认结束。普通情况默认保存有效学习时间，不要求用户猜测「放弃」是否会删除成果。

| 条件 | 记录与时长 | 经验 | 完成番茄 |
| --- | --- | --- | --- |
| 未满 60 秒提前结束 | 保留结束事件便于排障；不进入学习汇总 | 0 | 0 |
| 60 秒至不足 10 分钟 | ABANDONED，实际时长计统计 | 0，明确文案「已记录时长，满 10 分钟提前结束可获部分经验」 | 0 |
| ≥10 分钟、未到计划结束 | 默认保存实际时长；用户可选「领取部分经验」 | 选中时按 A.8 的 0.5 系数计奖；不选则 0 | 0 |
| 确认时已到计划结束 | 按完整完成处理 | 完整系数 | 1 |
| 提前结束休息 | 仅保留休息结果 | 0 | 0 |

「领取部分经验」默认选中，说明是完整经验的一半，不使用失败、扣分措辞；配置关闭部分经验时隐藏该选项，但已学习时间仍保留。用户不应通过反复结束后恢复同一会话重复获奖：**结算后只能新建会话，不可恢复运行**。

提前结束以服务端接收并确认的时刻为准。离线点击不能直接宣称已停止，见 A.7；后台已结算完整会话时，迟到的提前结束请求返回真实完成结果。

### A.6.5 休息与四次长休

- 短休默认 5 分钟、长休 15 分钟；只建议，用户手动开始。无论页面前后台都不自动开始下一次专注或休息，避免用户离开后被动计时。
- 当前学习日中每第 4、8、12…个完整番茄，成果卡将主操作改为「长休 15 分钟」。累计数按完成归属学习日计算；开始新学习日后重置。补录、提前结束不计入。
- 已建议长休后用户跳过，不持续弹窗追问。A 不做更复杂的连续专注批次管理。
- 休息跨页面可恢复；开始新专注前需要结束当前休息，可一键「结束休息并开始」，服务端原子切换，不能并行计时。

### A.6.6 提示音与通知

提示音、浏览器通知、动画是三个独立开关；默认轻提示音，提供试听与关闭。浏览器通知只在用户主动选择「开启结束提醒」时申请，不在注册或引导时弹权限。

页面打开且浏览器允许时尽力通知；锁屏、省电、系统权限和浏览器限制可能导致声音/通知不触发，设置页直白说明「后台提醒可能受系统限制，学习记录仍会保存」。A 不承诺关闭浏览器后准时唤醒。通知拒绝后仍能使用计时，不反复申请；从用户设置入口说明系统权限如何恢复。

## A.7 刷新、断网、多设备与计时准确性

### A.7.1 时间来源

- 服务端时间为业务依据；客户端展示使用服务端时间偏移与单调时钟推进。页面恢复前台、收到同步事件、网络恢复后重新校准。
- 不将浏览器 `setInterval` 或 Worker 回调次数作为真实时长；Worker 可以辅助刷新，但不是后台精确计时的保证。
- 服务端保存运行态到持久层；Redis 是缓存与互斥加速手段。缓存失效可恢复，会话唯一性必须能由数据库事务/唯一运行槽位保障。
- 设备系统时间前后改动不会改变服务端入账值。同步完成后、在线设备显示与服务端剩余时间差 ≤2 秒；离线期间不承诺这一跨设备误差。

### A.7.2 场景矩阵

| 场景 | 用户看到什么 | 系统必须做什么 |
| --- | --- | --- |
| 页面内跳转 | 顶部/底部紧凑计时条 | 复用同一会话，不重新 start |
| 刷新或浏览器重启 | 短暂恢复态后回到进行中/已完成 | 查询 current，再显示可执行按钮 |
| 页面后台十分钟 | 回来后立即校准剩余时间 | 不依赖后台 JS 是否运行 |
| 设备休眠后回来 | 已到时则展示保存结果 | 截止计划结束时刻，不累计睡眠后的额外时间 |
| 专注中断网 | 「离线中，计时继续；联网后确认结果」 | 已开始会话继续；禁止建立新的离线会话 |
| 离线到时 | 本地显示「已到时，等待联网确认」 | 不提前显示到账经验；服务端照常结算 |
| 离线提前结束 | 「当前无法确认结束，恢复网络后重试」 | 不把客户端离线点击时间当已确认结束；记录 pending 命令并说明暂未生效 |
| 联网后收到 pending 提前结束 | 显示实际服务端结果 | 若仍运行则先重新确认是否此刻结束；若已完成则展示完整结果，不用旧命令追溯扣时 |
| 开始请求超时 | 「正在确认是否已开始」 | 查询同一请求/当前会话，确认结果后再决策 |
| 结算请求超时 | 「正在核对，本次成果不会重复记录」 | 用 session_id 查询；同一会话最多一条奖励流水 |
| 两标签页/两设备打开 | 都展示同一倒计时 | 创建互斥；服务端广播或轮询同步 |
| 设备 A 正在专注，B 点击别的任务开始 | 「你正在专注于…」/继续该会话 | 不静默结束 A，不并行创建 |
| A 已结束，B 还显示运行 | 收到同步后更新结束结果 | 在线普通网络 5 秒内同步；B 的迟到写入返回已有结果 |
| Token 过期 | 尽量无感刷新；失败则登录入口 | 会话不丢，重新登录后恢复 |
| 服务重启、Redis 清空 | 短暂恢复，记录继续可查询 | 从数据库 RUNNING 恢复；过期会话补偿结算 |
| 同时到时和点击提前结束 | 显示一个最终结果 | 原子校验服务端时刻；只允许一次终态转换 |

**离线边界**：A 不是离线 PWA，不支持离线新建任务/补录/专注；页面已有未提交输入可以本地保留，但必须标注未同步，不能与「已保存」混淆。

**提前结束延迟**：实际结束以服务端确认时间为准，网络异常时会有偏差；用户可查看详细记录。A 不提供修改 TIMER 原始起止时间，也不把不可信客户端时间当成精确事实。若发现系统错误，可标记问题记录联系支持；支持修复必须有审计并联动冲正，不能悄悄改经验。

### A.8.1 经验计算

保留原十级阈值：`0 / 4000 / 10000 / 20000 / 36000 / 58000 / 90000 / 135000 / 195000 / 280000`。等级始终由累计经验推导，不同时维护可能互相矛盾的等级余额。

| 来源 | 计算 | 说明 |
| --- | --- | --- |
| 完整 TIMER 专注 | `floor(有效秒数 / 60 × 10)` | 25 分钟为 250；计时必须真正到时 |
| ≥10 分钟提前结束且领取部分经验 | `floor(有效秒数 / 60 × 10 × 0.5)` | 12 分 30 秒为 62；不足 10 分钟不奖励 |
| 手动补录/休息/任务勾选 | 0 | 可计学习时长的仅有效补录 |

每日奖励上限 9600 EXP。跨学习日的会话先按有效区间拆为各学习日，再按系数与各日剩余额度入账；每段向下取整，单段会话最多因跨界取整少 1 EXP。并发结算必须锁定相应学习日额度，不能各自读到同一剩余额度后超发。历史设置变更不重算已发经验。

例：25 分钟完整专注跨 00:00，前日 10 分钟、当日 15 分钟 → 前日基础 100、当日基础 150，分别受各日上限限制。若前日已到账 9550，则本次前日只到账 50，当日到账 150；成果卡显示共 200，并说明前日已达上限。

上限达到后显示「今日成长经验已满，学习时间会继续记录」。不鼓励为了满级追求 16 小时学习。等级满级后继续记录学习与累计经验，UI 展示「已到最高等级」，不出现负数/除零进度条，不承诺 A 未实现的后续奖励。

### A.8.2 成长可感知但不打扰

- 保留五种宠物，经验和等级属于账号成长，切换伙伴不重置，也不为每只新开经验账本。切换前展示预览和一句说明。
- 普通专注完成：数字增长与宠物短动作，约 0.8–1.5 秒，可立即操作后续按钮；不强制观看。
- 升级：在同一成果卡中展示「Lv.2 → Lv.3」，不中断用户刚开始的新会话。四阶段变化分别为 Lv.1–3、4–6、7–9、10。
- 同次多级成长合并为一张结果卡，展示起止等级，**替代原文逐级全屏播放要求**。低频彩带控制在约 2 秒内且可跳过；默认不做持续满屏粒子。
- 未到等级变化时也展示本次到账经验和下一阶段进度，让第一次 25 分钟有可感知反馈。阈值保留原基线，是否调整需通过用户反馈验证，不在无说明时更换老用户曲线。
- 非专注页面宠物卡可收起；专注时以安静陪读为主。图片资源加载失败显示稳定占位形象，不挡住计时与操作。
- 低动态偏好下关闭彩带、呼吸和位移动画；静音后升级不能绕过声音设置。夜间主题不突然闪白。
- 缺席不生病、不扣经验；「想你了」等温和文案每次回访最多一条，不制造负担。

## A.9 补录与最小专注记录

### A.9.1 录入

入口：专注页「补录学习」和记录页的补录按钮，不占据首页主操作。字段为科目、起止日期时间、可选任务、可选备注。

| 校验 | 规则与反馈 |
| --- | --- |
| 时间 | 结束必须晚于开始；不得晚于服务端当前时间；单次 1 分钟–4 小时 |
| 重叠 | 不得与 TIMER 已结算有效区间、其他有效 MANUAL 区间、当前运行会话已占用/预留区间重叠 |
| 边界 | 使用半开区间 `[start,end)`；10:00–10:30 和 10:30–11:00 可以相邻 |
| 跨日 | 可跨日、跨学习日起点；保存前显示分别计入哪些学习日和时长 |
| 科目 | 必选；归档科目默认不在新增候选中 |
| 冲突 | 显示冲突记录的时间与科目，并提供查看；保留表单输入 |

A 支持任意过去日期补录；日期很久远时提示确认，不武断禁止。不得借补录生成宠物经验或完整番茄数。

同账号记录写入和会话创建必须串行校验区间，避免两个同时提交的补录都通过先查后写。补录时存在运行会话：允许提交不相交的历史区间；与当前会话预留区间相交则先处理该会话。

### A.9.2 列表、修正与删除

- 默认当前学习日，支持前后翻日、选日期、按科目筛选；每条显示分秒、科目、任务快照、来源（计时/补录）、结果（完整/提前结束）、经验值。
- 跨学习日会话在各日显示其当日切片及「完整记录共 N 分钟」，有同一 session_id 关联；不能把一条完整记录在两天各算一次。
- 补录可编辑、删除，编辑重新查重；删除提供 5 秒撤销，服务端每次版本校验。有效时长、首页、周目标同步更新，不触碰宠物经验。
- TIMER 不允许在 A 编辑时长或直接删除以刷奖；记录里给出「数据有问题」入口。账号注销仍必须删除这类个人数据。未来增加更正功能必须先设计经验冲正，不能只改展示。
- 默认分页 20 条，继续加载保持位置；数据错误显示重试入口，真实无记录才显示空状态。

## A.10 首页数字与统计口径

| 数字 | 分子/分母或算法 | 边界 |
| --- | --- | --- |
| 今日专注时长 | 当前学习日的已结算有效时间切片之和 | 运行中预估额外标「进行中约 X 分钟」，不混为已入账 |

周目标可不设置；完整引导提供用户可确认的建议值，不自动套用原 35 小时作为每个人的强制目标。已设置用户沿用原值，变更时仅影响目标对照，不重写学习记录。

首页 2 小时、列表 120 分钟、后续 B 图表的和必须来自同一套有效时间切片；前端不能分别用三套公式。缓存落后时以结算返回值或主动刷新弥合，并标记刷新中，不能让旧响应覆盖新数据。

## A.11 视觉、移动端与可访问性

### A.11.1 视觉基线

- 采用简约鲸蓝与毛玻璃：雾白/浅灰蓝背景、深海蓝功能强调、少量磨砂表面；正文、数字与操作优先清晰，具体颜色、组件与降级规范见 A.11.3–A.11.5。主题覆盖准备态、弹层、错误态和空态，不只替换页面背景。
- 建议字号：正文桌面 14–16px、移动端 16px；辅助信息不低于 12px。计时数字使用等宽数字，长度变化不引发左右跳动。
- 建议间距基于 4/8px，卡片 16–24px 内边距；移动端主按钮最小高 44px，点击区域至少 44×44px。圆角按组件层级区分，不要求每个微小控件都大于 16px。
- 正文对比度至少 4.5:1，大字号与可视控件边界按可访问性要求验证；科目颜色另配名称，任务状态另配图标/文字，不能只靠颜色。
- 毛玻璃用于有限的层级表达，正文和列表提高不透明度；背景柔光、透明效果和伙伴不能推迟主任务按钮显示。避免多层模糊叠加、强渐变和重阴影；关闭透明效果时仍有清晰边界与层次。

### A.11.2 移动端细节

1. 375px 首屏能看到任务/直接专注入口，不需要先滚过大宠物图；320px 到大屏布局都可正常阅读，关键验收至少覆盖 375/390/768/1440px。
2. 表单软键盘弹出后，标题输入和提交按钮可见；避免固定底栏遮挡，兼顾横屏、刘海与底部安全区。
3. 任务详情、科目选择、提前结束使用可滚动底部面板；不能依赖悬停才出现的操作。详情关闭返回原列表位置。
4. 没有拖拽能力的用户可用上移/下移；长标题换行或两行截断，详情可查看全文。数字和按钮不被标题挤出屏幕。
5. 宠物动画不覆盖专注操作；计时倒数不每秒播报给屏幕阅读器，只在开始、即将结束/结束等节点提供简短语义提示。
6. 键盘可访问所有按钮与弹层，焦点清晰；弹层打开焦点进入，关闭返回来源，Esc 可关闭非破坏性弹层。系统字体放大 200% 时主流程仍能完成。
7. 应用默认跟随系统主题；用户手选浅/深后覆盖系统且跨设备保存。首次主题读取前避免白屏闪烁。

### A.11.3 已确认的简约鲸蓝毛玻璃方向

**风格决定：简约、鲸蓝色调与毛玻璃。** 以雾白/浅灰蓝为大面积底色，以低饱和深海蓝建立品牌识别，用少量半透明磨砂容器表现层次。鲸蓝在本产品中指下表定义的色系，不代表要加入鲸鱼吉祥物、海景照片或海浪动效；五种伙伴的业务设定继续保留。

| 层级 | 视觉要求 | 使用范围 |
| --- | --- | --- |
| 页面背景 | 雾白/浅灰蓝，极淡静态柔光，可使用1–2处大面积低对比色晕 | 不能透过面板形成可辨识文字、图像或明显花纹 |
| 主色 | 克制、稳定的鲸蓝 | 主按钮、链接、选中、焦点、关键数据与进度 |
| 毛玻璃 | 半透明、适度背景模糊、细边框与轻阴影 | 导航、顶部栏、快速专注等少量重点表面；同一区域不嵌套多层模糊 |
| 数据与正文 | 高不透明度或实色表面，细分隔线 | 今日任务、最近记录、表单、说明文字与数据图条；不牺牲阅读清晰度 |
| 伙伴 | 简洁柔和插画或轻量立体表现 | 保留五种伙伴与四阶段识别，尺寸紧凑，不盖住操作 |
| 状态色 | 克制的成功绿、警告琥珀、错误红，配文字/图标 | 用于真实状态；不作为背景装饰和全页多色配色 |

不再使用水墨山水、宣纸纹理、书法字形或朱红印章作为当前设计元素。此前概念图仅可参考功能布局，不能直接用于新主题的背景或样式；鲸蓝毛玻璃视觉稿需按当前规范重新设计。

控制台信息结构、四项指标、任务/专注双栏、科目投入和最近记录继续遵守 A.2。毛玻璃不意味着每个任务行都是一张卡片；列表保持整体分组与轻分隔，一个页面保留一个最明显的开始/继续主操作。

### A.11.5 透明度、动态、主题与性能降级

- **降低透明度**：在设置的「伙伴与显示」分组提供独立开关，开启后玻璃面板改为 `surface-solid`、关闭背景模糊并简化柔光；不改变布局、操作入口或数据。默认保留毛玻璃；偏好持久化，换设备可恢复。
- **降低动态效果**：与透明度开关独立。A默认静态背景，不做持续漂移光斑、波浪、视差或自动播放背景；短时交互反馈和伙伴动作受低动态与静音设置控制。
- **不支持/设备降级**：背景模糊能力不可用或设备持续卡顿时，回退实色面板。降级只影响本次有效渲染，不悄悄覆写用户保存的透明度偏好；无模糊时仍有分隔、层次和清晰焦点。
- **移动端**：缩小或关闭背景模糊，避免多层固定透明面板同时覆盖大面积内容；滚动、输入与计时操作优先。保留鲸蓝色系与组件层级，不通过降低字号保留装饰。
- **浅/深/系统主题**：深色使用深海蓝灰背景、较高不透明度面板与浅色文本，不把浅色主题简单反相；链接、选中、错误、禁用和焦点逐状态复核，首次载入不闪白。
- **内容与资源**：基础背景和可操作内容先出现，玻璃效果渐进增强；伙伴/装饰加载失败不阻断任务和开始按钮。图像资源保持原创或授权，视觉资源不与业务数据绑定。
- **性能验收**：模糊不能突破A.14首屏/交互指标；在代表性移动设备上验证列表滚动与键盘输入，不因持续重绘出现明显卡顿。若不达标，减少模糊覆盖/层数或默认实色，不牺牲计时可靠性换取效果。

## A.12 加载、失败、冲突与文案

### A.12.1 组件必须具有的状态

| 状态 | 展示 | 用户下一步 |
| --- | --- | --- |
| 首次加载 | 与真实布局相同的骨架，保留页面标题 | 不显示假任务或假进度 |
| 局部刷新 | 原数据保留，局部进度提示 | 仍可查看旧数据，写入受必要限制 |
| 真实空态 | 一句原因 + 一个具体操作 | 添加任务/直接专注/调整筛选 |
| 网络失败 | 友好说明 + 重试，保留页面输入 | 重试；明确哪些操作尚未保存 |
| 部分模块失败 | 失败卡独立重试，其他模块可用 | 例如宠物失败不阻断开始专注 |
| 权限/登录过期 | 登录入口，保护草稿 | 登录后回原页面 |
| 并发版本冲突 | 「这项内容已在另一设备更新」 | 载入最新；保留自己待提交内容供重新应用 |
| 服务维护 | 明确状态、重试/支持入口 | 不显示一页异常堆栈或数据库信息 |

### A.12.2 标准文案示例

| 场景 | 使用文案 | 避免的文案/行为 |
| --- | --- | --- |
| 提前结束并记录 | 「这次已记录 12 分钟，稍后再继续也可以」 | 「专注失败，宠物很失望」 |
| 有待处理任务 | 「有 4 件任务可以重新安排」 | 「你已严重逾期 4 项」 |
| 保存未确认 | 「正在确认保存结果，请稍候」 | 直接提示成功、实际未入账 |
| 记录冲突 | 「这段时间与 14:00–14:25 的高数记录重叠，请调整」 | 裸错误码或直接清空表单 |
| 科目归档 | 「归档后不再用于新任务，历史记录仍保留」 | 「删除后所有数据可能丢失」却不明确后果 |
| 目标未设置 | 「设置目标日期，方便查看剩余时间」 | 强制弹窗直到填写 |
| 全部完成 | 「今天安排的事做完了，休息一下吧」 | 默认再追加更多任务 |

Toast 不作为唯一保存凭证；记录列表和状态标签能长期核对结果。成功提示通常约 2 秒，不连续叠加；错误提示保留可操作入口，不因两秒后消失而无法修复。

## A.13 设置与数据保护

| 分组 | A 范围 | 生效方式 |
| --- | --- | --- |
| 个人与目标 | 昵称、头像、单一目标名称/日期 | 保存后首页同步；不要求实名 |
| 科目 | 新增、改名、排序、归档/恢复 | 名称去首尾空格，1–50 字符；有效科目名称不重复 |
| 专注 | 默认时长、结束提示音、通知授权状态 | 默认时长影响下一次；不修改正在运行会话 |
| 伙伴与显示 | 更换伙伴、浅/深/系统主题、降低动态效果、降低透明度 | 立即生效并保存偏好，等级不重置；透明度与动态开关独立 |
| 统计规则 | 时区、学习日起点 0–6 点、可选周目标 | 时区/日起点遵守 A.1 延后生效规则；保存前展示影响 |
| 账号 | 修改密码、退出登录、注销 | 高风险动作要求近期身份确认 |

科目有历史记录或关联未完成任务时不可直接物理删除。归档前若还有未完成任务，提供「迁移到其他科目 / 同时取消这些任务 / 返回」；不允许让任务关联变成悬空。最后一门有效科目不能归档；运行会话所属科目先结束会话再归档。

头像仅允许 jpg/png/webp，建议 ≤2MB，失败可重试；服务端校验实际文件类型和访问归属，不信任扩展名。选头像与填写昵称都不得阻断第一段专注。

注销先展示数据范围和后果，要求密码或近期验证，说明是否仍有运行会话，并先停止/结清会话、撤销令牌再异步清理个人数据。删除作业必须覆盖任务、会话、经验、头像和缓存，支持失败重试；已注销身份不能再次收到奖励或提醒。备份数据按实际备份保留周期过期，不承诺瞬时清除所有备份。界面文案必须与实际删除机制一致。

专注记录、任务和个人资料默认私有；AI 属 B/C，A 不因为未来要做 AI 就预先获取日志发送同意。完整导出属于 B，A 的反馈/支持入口必须真实可用，并说明可查看的数据范围。

## A.14 性能与可靠性验收环境

以下是建议上线基线，需在预发布环境测量；结果记录设备、网络、版本、样本量，不只写「感觉很流畅」。

| 项目 | 测量方式 | 目标 |
| --- | --- | --- |
| 首次可开始操作 | 冷缓存、约 10Mbps 下行/150ms RTT、移动设备或中端 CPU 限速，首页导航开始至主开始按钮可响应 | P75 ≤3 秒；路由与图表等非 A 主包懒加载 |
| 本地点击反馈 | 点击/键盘操作至按钮或状态变化 | 通常 ≤100ms；较慢请求有处理中状态 |
| 任务新增视觉反馈 | Enter 后出现保存中条目 | ≤300ms；接口成功后再确认完成 |
| 核心写接口 | 预发布 100 个同时在线会话、合理任务数据，单接口不少于 200 个样本 | 开始/结算/任务写入 P95 ≤500ms；错误率单独报告 |
| 会话恢复 | 在线普通网络，当前会话查询完成至准确显示 | 查询响应后 ≤1 秒；总流程 P95 ≤2 秒 |
| 到期入账 | 服务端计划结束至持久化完成 | 正常情况下 ≤5 秒；恢复查询同步补偿可得到正确结果 |
| 跨设备同步 | 在线普通网络，一端完成至另一端看到终态 | ≤5 秒；无网络时不承诺 |
| 大任务量 | 账号累计 5000 条任务、10000 条专注记录 | 今日分页与开始不因全量加载卡住；记录分页可用 |
| 数据恢复 | 模拟服务重启、Redis 清空、重复结算 | 无重复时长/奖励，当前会话可从持久层恢复 |

浏览器验收选择发布时团队明确支持的 Chrome/Edge/Firefox/Safari 版本及真实 iOS Safari、Android Chrome；记录版本号，不把「支持所有浏览器」作为结论。通知/音频被限制时主流程仍可使用。

保留原每日备份、7 天保留建议，并至少演练一次恢复；暂定恢复点目标 ≤24 小时、恢复时间目标 ≤4 小时。上述目标只有在真实备份、恢复脚本与值守机制可达成时才能写入对外承诺。

### A.15.2 发布前实测

找至少 5 位接近目标用户的人，不讲解界面，依次做：①首次注册并开始学习；②新增任务并在 12 分钟后提前结束（测试环境可时间加速）；③刷新/切设备恢复；④顺延一项旧任务；⑤补录且处理时间冲突；⑥关闭声音与通知。

## A.17 给研发的最小增量契约

本节只规定体验成立需要的数据与语义，不代替详细技术设计。保留原 Spring Boot / Vue / MySQL / Redis 架构；接口命名可在评审统一，不能因命名差异改变业务规则。

### A.17.1 数据模型增量

| 对象 | 原稿缺口 | 必须支持 |
| --- | --- | --- |
| 用户与设置 | 日期、主题默认、显示效果与时区变更语义不完整 | 昵称、可空目标日期/周目标、主题 SYSTEM、静音/动态偏好、`transparency_mode=GLASS/SOLID`（默认GLASS）、已确认默认科目、引导步骤进度 |
| 控制台摘要 | 独立计算容易出现指标、列表、图条不一致 | 学习日、规则版本、聚合数据版本/更新时间、任务完整计数、科目有效秒数、最近记录来源与结果 |
| 统计规则版本 | 一个全局 timezone/day_start 无法保护历史 | effective_at、timezone、day_start、version；切片/会话记录采用的版本 |
| 任务 | 原状态只有 TODO/DONE，无取消/版本/追溯 | CANCELLED、updated_at、version、original_target_date、完成/取消时间、软删除与调度记录 |
| 重复模板 | repeat_rule 混在任务里，无法区分模板/实例 | 独立模板、有效起止日、停用、指定周几、版本；实例唯一约束 |
| 导入批次 | 超时后不能可靠去重 | request_id、template_version、batch_id、模板条目标识和目标日映射 |
| 专注会话 | duration_minutes 混淆计划和实际，结束状态不足 | planned_seconds、actual_seconds、scheduled_end_at、ended_at、end_reason、结算版本/时间、请求幂等键 |
| 唯一运行态 | Redis 锁丢失可能并行开始 | 数据库可证明的用户运行槽位或等价约束；专注/休息共用 |
| 时长分摊 | 单个 stat_date 不能表达跨日/跨小时 | 由真实区间生成日/小时切片；可重建汇总，保存规则版本，不重复累计 |
| 经验账本 | 只有累计经验难以去重和解释 | session_id、学习日、系数、实际奖励、当日限额、规则版本；唯一约束和每日额度锁 |
| 成果展示 | 多端可能连弹/重复庆祝 | 服务端 presentation_claim/ack 与状态同步，实际领奖由结算控制而非前端弹窗控制 |
| 手动记录 | 并发先查重后写入不安全 | 用户维度互斥/事务化区间校验、版本更新、编辑删除撤销与汇总更新 |
| 账号找回 | 原稿将其放二期 | 若公网开放则提前支持已验证邮箱、一次性重置令牌、失效与审计 |

保留 BCrypt 时必须处理其输入字节上限：密码 8–64 字符且 UTF-8 编码 ≤72 字节，前后端一致校验，超限明确提示，不允许静默截断。表单帮助应说明支持密码管理器与粘贴。若后续替换哈希算法，使用带算法标识的编码与旧密码渐进迁移，不直接使老账号无法登录。

### A.17.2 业务接口与错误恢复

| 能力 | 建议契约 | 客户端处理 |
| --- | --- | --- |
| 控制台聚合 | 返回学习日/规则版本、四项指标、任务摘要、当日科目投入、最近记录、updated_at/data_version | 模块错误可独立表达，不用失败值覆盖已确认数据；当前会话仍经统一恢复接口核实 |
| 开始专注/休息 | 返回 session_id、server_now、start_at、scheduled_end_at、当前配置快照 | 不用本地计数确定事实；幂等重试 |
| 查询 current | 返回运行会话；无运行时可带最近未确认结果 | 恢复入口统一，过期会话先补偿结算 |
| 结束/complete | session_id + request_id；返回实际终态、有效秒数、奖励明细、宠物状态、日汇总版本 | 已结算请求返回相同业务结果，无二次奖励 |
| 专注记录 | 日期/科目/分页；返回来源、区间、归属切片、任务快照 | 不用任务当前名称代替历史快照 |
| 更新任务/排序 | 提交 version/expected_version，批量操作返回明确结果 | 冲突保留输入；不能只覆盖最后写入 |
| 导入模板 | request_id + preview_version + 选中条目 | 预览版本过期要求重新确认；原子批次 |
| 补录/编辑 | 完整区间 + version；冲突返回可展示的重叠摘要 | 不清空表单，可跳转核对 |
| 统计规则变更 | 返回旧版、新版、生效时刻和影响说明 | 保存前后文案一致；运行中拒绝变更 |

统一错误除 code/message 外，建议返回 `traceId/retryable/fieldErrors/currentVersion/currentSession` 中适用部分。比如 `SESSION_EXISTS` 应能直接继续已有会话；`VERSION_CONFLICT` 应能加载最新；`TIME_OVERLAP` 应能展示冲突记录。业务错误不返回堆栈、SQL 或其他用户数据。

关键数据操作必须支持至少 24 小时的请求幂等结果查询；到期后仍以业务唯一约束保证不重复。查询 current、读取记录不会重新发奖。数据库为事实源，汇总/缓存可重建，修复有审计。

## A.19 本次补充的关键决策与评审项

### A.19.1 本版建议默认采用

1. 核心闭环独立上线，控制台是一期-A 默认首页，主导航为控制台/任务/专注；数据摘要与快速专注可用。
2. 引导可跳过，目标日期不强制；伙伴和科目有可见默认值；模板先预览、只生近期任务。
3. 任务完成与计时结束分离；旧任务只提示重新安排，不自动堆到今天；子任务不双算完成率。
4. 服务端到时才算完整番茄；不采用 95% 判定；不自动开始下一段；离线状态如实标注。
5. 提前结束可保留时间；满十分钟可半奖；补录只记录真实时间、不产生经验。
6. 跨日按真实时间切片，日限额按切片日执行；时区/日起点变更不改历史事实。
7. 一次结果只结算一次，多级成长一张卡；缺席不惩罚，通知授权不强迫。
8. 最小记录列表、幂等、版本冲突、备份恢复和移动端可操作性是体验基础，不作为装饰性优化留到最后。
9. 当前视觉统一为简约鲸蓝毛玻璃；内容清晰度、控制台信息密度与性能优先，透明度和动态偏好可独立关闭并保存。
