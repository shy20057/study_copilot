# 一期 A 后端运维说明

[返回文档导航](../README.md)

本文记录 2026-10-23 补齐的后端运维相关实现。根据用户本轮仅开发代码的要求，尚未编译、启动、执行迁移或测试。下列命令仅供后续运维操作参考，不代表已经执行。当前范围见 [交付说明](../04-交付验收/一期A后端交付说明.md)，环境准备见 [本地开发说明](../02-开发指南/后端本地开发.md)。

## 配置与服务边界

使用 Java 17、PostgreSQL 16 和现有中间件。按照本地开发说明提供数据库、JWT、独立幂等 HMAC 密钥和人工恢复渠道环境变量。一期 A 不启用 `future-features` 或 `legacy-api` 配置。

| 环境变量 | 默认值与用途 |
| --- | --- |
| `SC_MINIO_ENDPOINT` | `http://127.0.0.1:9000`；MinIO 接口地址，不是控制台地址 |
| `SC_MINIO_BUCKET` | `study-copilot`；专用私有头像存储桶 |
| `SC_MINIO_ACCESS_KEY`、`SC_MINIO_SECRET_KEY` | 仅限头像桶的凭据；为空时头像功能不可用，但不阻止核心应用启动 |
| `SC_METRICS_TOKEN` | `/actuator/prometheus` 的可选独立访问密钥；未配置时拒绝访问 |
| `SC_FOCUS_SCAN_DELAY_MS` | `1000`；到期专注扫描间隔，单位毫秒，每批最多处理 50 个用户 |
| `SC_ACCOUNT_DELETION_SCAN_DELAY_MS` | `30000`；账户清理扫描间隔，单位毫秒，每批最多处理 20 个到期任务 |

MinIO 客户端在首次头像操作时初始化，创建应用组件时不连接存储服务。请求设有连接、读取、写入超时，以及 30 秒的整次 HTTP 调用超时。存储桶由运维人员预先创建，应用不会创建桶或修改公开访问策略。应使用未启用对象版本控制和对象锁的私有桶；当前实现只删除当前对象，不清理历史版本或处于保留锁定状态的数据。

调度器使用两个线程，避免清理账户时的存储或缓存故障占用唯一的专注结算线程。每秒扫描只是配置，不能证明已达到需求中的 5 秒结算目标，发布前仍需实测负载下的延迟。

V6 为 `t_attachment` 增加私有头像元数据，为 `t_user` 增加独立的 `profile_version`，V1–V5 不变。V7 增加任务变更批次、重复任务生成状态、完整番茄归属日、补录备注、整数秒分配支持、持久化登录限流、延迟生效规则序列和反馈偏好。升级前备份，后续获准启动应用时由 Flyway 执行 V6、V7。本轮既未验证空库迁移，也未验证已有数据库升级。

## 私有头像

- `POST /api/upload/image`：使用多部分表单字段 `file`，携带正常访问令牌。限制为 **2,097,152 字节**，识别 JPEG、PNG、WebP 的文件签名和容器标记，存储格式不依赖客户端声称的文件名或类型。这是文件签名与容器校验，不包含病毒扫描或完整像素解码。
- 上传成功沿用 `Result<String>` 结构，`data` 为 `/api/upload/images/{attachmentId}`。同一事务记录元数据并更新当前用户头像。
- `GET /api/account/profile`：返回 `username`、可空的 `nickname`、可空的 `avatarUrl` 和 `version`，页面刷新后可恢复头像。
- `PUT /api/account/profile`：接收 `nickname`（去除首尾空格后 1–50 字符）和 `expectedVersion`，返回更新后的资料。上传头像也递增该独立资料版本。版本过期时返回 `VERSION_CONFLICT` 及 `currentVersion`，避免覆盖其他设备的修改。
- `GET /api/upload/images/{attachmentId}`：要求资源所有者的访问令牌，返回检测出的图片类型，并设置 `no-store`、`nosniff`。他人附件 ID，以及缺少私有元数据的旧附件返回 404。
- 浏览器图片标签不会自动附加应用访问令牌。前端应通过已认证的接口客户端读取图片，创建 Blob URL，替换头像或退出时释放该地址。不要把令牌放进图片地址的查询参数。

对象键完全由服务端生成，格式为 `users/{userId}/avatars/{uuid}.{jpg|png|webp}`，不接受客户端提交对象键或公开存储桶地址。上传和读取均先锁定有效用户，再访问依赖记录或存储，与账户注销串行执行。

不支持的内容返回 `SC_016001`、HTTP 415；图片过大返回 `SC_016002`、HTTP 413；存储故障返回 `SC_016003`、HTTP 503，并设置 `retryable=true`。上传失败不会替换当前头像。数据库回滚时会尝试删除新对象，存储不可用时可能留下孤立文件，账户清理会遍历该用户完整前缀，包含此类残留。替换下来的旧头像在账户清理前保持私有；尚未实现有效账户的孤立文件或旧头像定期清理器。

## 账户注销

`POST /api/account/deletion` 需要正常访问令牌，请求 JSON 包含 `currentPassword` 和 `confirmDeletion:true`。不要把请求体记录到日志或请求追踪中。接口返回 HTTP 202、统一响应结构，以及 `data:{jobId,status:"PENDING"}`。

请求事务先锁定用户行，验证当前密码，再取消进行中的专注或休息，不产生新经验。随后将用户标记为 `status=2`（等待注销）、`deleted=1`，递增 `session_version`，撤销全部刷新会话，并写入 `t_account_deletion_job`。密码校验失败或事务失败均不执行上述变更。用户与任务唯一约束及用户锁防止重复清理任务。提交后，登录、刷新、访问校验和写操作幂等重放均拒绝该账户；旧令牌不能用来轮询注销状态。前端保留回执，需要确认时联系配置的人工恢复或支持渠道。

后台清理器依次获取用户锁和任务锁，在多应用实例间对用户使用 `SKIP LOCKED` 跳过已锁记录。持有用户锁期间，按以下顺序清理：

1. 删除该用户完整的 MinIO 头像前缀，包括未写入数据库的上传残留。
2. 使用 `SCAN` 仅删除 `${study-copilot.redis-key-prefix}user:{userId}:*` 缓存键。配置中的通配符会转义，不执行 Redis 全量清空。当前模块尚未写入用户缓存，后续写入必须遵循该命名空间和用户锁约定。
3. 按外键顺序删除用户数据：成果展示领取记录、奖励、切片、会话、日程、任务、重复模板与导入批次、引导、设置、规则、科目、伙伴、附件元数据、刷新与幂等数据，以及旧 B/C 数据。
4. 将用户名和规范化用户名替换为相同的随机审计占位值，移除密码哈希、邮箱、昵称、头像及活动时间。保留用户 ID 与账户、注销时间供任务审计，任务标记为 `COMPLETED`，固定结果不含个人内容。

旧登录名仅在清理提交后释放。系统保留最小审计记录，不物理删除用户主键。历史个人事实随清理移除，注销本身不产生奖励或成果展示。在注销获取用户锁前已提交的结算属于更早的有效事务，其记录随后一并清理。

任一外部清理或数据库故障会回滚数据库删除，已经成功的对象或缓存删除可安全重试。清理器仅记录固定范围的错误码，按 30、60、120 秒逐步退避，最长 1 小时，另加扫描间隔。进程崩溃会回滚未提交的 `RUNNING` 状态，持久化任务仍可在后续扫描重试。MinIO 或 Redis 故障期间，账户保持撤销状态，清理任务保持可重试，不恢复账户访问。不要为重试清理而恢复有效身份。

运维人员可查询任务，不读取个人内容：

```sql
select id, user_id, status, retry_count, next_attempt_at, last_error_code, completed_at
from study_copilot.t_account_deletion_job
where status <> 'COMPLETED'
order by next_attempt_at, id;
```

故障解决后，清理器自动重试。如需立即推进某个 `RETRY` 任务，获授权的运维人员可按任务 ID 将 `next_attempt_at` 设置为 `now()`，仍保持先用户、后任务的加锁顺序。不要手动修改个人或奖励数据，也不要将未完成任务标记为 `COMPLETED`。

## 健康检查与指标

`GET /actuator/health` 提供公开的汇总健康检查，详细信息遵循健康检查与安全配置。`/actuator/prometheus` 仅接受 `Authorization: Bearer <SC_METRICS_TOKEN>`，与应用 JWT 密钥独立校验。使用密钥管理服务或 Prometheus 令牌文件，通过内网或部署代理保护端点，不要将令牌放进 URL。其他 Actuator 端点保留管理员角色限制，普通应用用户不授予管理员角色。

已引入 Prometheus 指标注册依赖。下表为 Micrometer 指标名，Prometheus 会将点转换为下划线，并添加相应计时器或计数器后缀。

| 指标名 | 含义 |
| --- | --- |
| `study_copilot.api.requests` | 按固定操作类别 `operation` 和 HTTP 状态类别统计请求数 |
| `study_copilot.api.duration` | 使用相同固定范围标签的请求耗时 |
| `study_copilot.api.errors` | 已定义错误码的次数，包含安全过滤链拒绝 |
| `study_copilot.idempotency.replays` | 共享认证写操作的成功重放次数；注册使用独立重放路径 |
| `study_copilot.focus.settlement.delay` | 从计划结束到完整结算提交的延迟，包含恢复触发的结算 |
| `study_copilot.account.cleanup` | 清理完成或进入重试的次数 |

操作类别涵盖注册、登录、刷新、退出、任务写入、会话开始与结束及恢复、记录恢复、头像和账户注销。标签不包含用户 ID、资源 ID、追踪 ID、原始 URL、请求体或凭据。请求指标描述 HTTP 结果；结算耗时在事务提交后记录。这些是运维尝试次数和延迟，不是去重后的产品行为统计。

监控错误率、耗时、超过 5 秒目标的结算延迟，以及未完成注销任务的等待时间和重试次数。健康检查与指标不能证明备份正确、应用已就绪或验收通过。

## 恢复与备份

PostgreSQL 是事实数据来源。应用重启或 Redis 数据丢失后，应通过 `/api/focus/current` 和后台到期扫描恢复会话。Redis 不承担经验或会话账本，不要通过清空共享 Redis 恢复应用。有效账户的头像故障返回可重试存储错误，不改动任务或专注事实。

部署环境通过环境变量或密钥文件提供数据库凭据，命令和文档中不写明文密码。运维备份流程应满足：

1. 每日仅对 `study_copilot` 执行自定义格式的 `pg_dump`，加密归档并限制访问。按照实际存储桶策略备份 MinIO 头像，数据库备份保留注销任务和审计记录。
2. 按约定的 7 天窗口保留备份，到期同步清理数据库与对象备份。仓库不安装备份调度任务；数据库文件保留由后述脚本执行，对象备份保留仍需部署环境配置。
3. 使用 `pg_restore` 恢复到单独准备的数据库，不直接覆盖线上库。核对迁移与结构版本、事实数量及代表性会话和奖励关联。按照用户的项目要求，执行功能检查需要另获测试批准。
4. 恢复库接入流量前，利用保留的注销审计核对备份之后的新注销请求并完成清理。轮换或撤销恢复出的刷新会话，避免旧备份重新激活访问。
5. 记录恢复日期、备份日期、目标数据库、实测时长、操作人和差异。需求中的恢复点目标（RPO）不超过 24 小时、恢复时间目标（RTO）不超过 4 小时，仍需实际演练证明。

本轮未执行备份、恢复、保留策略配置、外部对象删除或账户注销。备份数据按照实际配置的 7 天保留策略逐步过期，不承诺立即从全部备份中删除。

## 本轮补齐的运维相关代码

登录限流保存在 `t_auth_throttle`，独立于可能失败回滚的登录事务。使用独立幂等密钥，对规范化账户标识和来源标识计算 HMAC，表内不保存原始用户名或 IP。账户在 15 分钟内达到 5 次尝试后，从 1 秒开始渐进退避，最长 15 分钟；成功登录重置账户计数。来源在 15 分钟内达到 300 次后开始退避，最长 60 秒，以兼容共享网络。拒绝响应提供 `retryAfterSeconds` 和 `Retry-After`。记录 24 小时后过期，注销也移除账户限流标识。来源采用直接连接地址，不信任客户端转发头。

重复任务调度器每 30 秒扫描一次，每批最多 100 个用户，仅处理最近 5 分钟活跃的用户；首次访问始终补偿当前学习日，不循环补齐离线期间的历史日期。认证活动时间最多每分钟更新一次，跨过离线日期生成的实例标记 `backlog_skipped`。后台与前台采用相同的先用户加锁顺序，多实例使用 `SKIP LOCKED` 协调。

`scripts/backup-backend.ps1` 写入自定义格式数据库归档，仅在 `pg_dump` 成功后转为正式文件，再清除自身命名规则下超出保留期的归档，默认保留 7 天。备份失败时保留已有归档。需提供专用受保护或加密目录及私有 PostgreSQL 客户端环境凭据。脚本不备份 MinIO，也不安装调度器，部署环境需安排对象备份和每日执行。

`scripts/restore-backend.ps1` 仅接受已存在且为空、名称符合 `study_copilot_restore_*` 的数据库，不接受线上或测试库，也不使用破坏性的清空选项。恢复后的数据核对、会话撤销和注销审计仍按前文执行。本轮未运行这两个脚本，`backend/Dockerfile` 也仅交付源码，未构建容器。
